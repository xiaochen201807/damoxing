## 四、数据库脚本执行说明

### 1. 已上线旧库执行脚本

已存在业务标准相关基础表的环境，优先执行各数据库对应的升级脚本：

- Oracle：`server/data/upgrade_business_standards_online_oracle.sql`
- 达梦：`server/data/upgrade_business_standards_online_dm.sql`
- PostgreSQL：`server/data/upgrade_business_standards_online_pg.sql`
- GaussDB：`server/data/upgrade_business_standards_online_gauss.sql`
- 人大金仓：`server/data/upgrade_business_standards_online_kingbase.sql`

上述脚本当前主要覆盖改造点 `2、3、4、5、8、9、10` 的数据库结构变更，脚本均按“对象不存在才创建、字段不存在才新增”思路整理，可用于已上线库增量升级。

### 2. 新建环境初始化脚本

如果是新建库或初始化部署，可直接执行各数据库对应的初始化脚本：

- Oracle：`server/data/init_business_standards_oracle.sql`
- 达梦：`server/data/init_business_standards_dm.sql`
- PostgreSQL：`server/data/init_business_standards_pg.sql`
- GaussDB：`server/data/init_business_standards_gauss.sql`
- 人大金仓：`server/data/init_business_standards_kingbase.sql`

初始化脚本包含当前业务标准主流程所需核心表结构，适用于全新环境一次性建表。

### 3. 存储过程与基础数据补充脚本

改造点 `6` 属于存储过程/函数层升级，不在上述“业务标准升级脚本”主表结构范围内，需按数据库类型额外执行过程脚本。

改造点 `2` 的业务内容分类表 `gjj_ywnrfl` 建表后，还需要补齐基础数据。现场需补执行如下脚本：

- 业务内容分类基础数据--oracle：``server/data/seed_ywnrfl_gjsjsf_1_oracle.sql``
- 业务内容分类基础数据--达梦：`server/data/seed_ywnrfl_gjsjsf_1_dm.sql`
- 业务内容分类基础数据--postgresql：`server/data/seed_ywnrfl_gjsjsf_1_pg.sql`
- 业务内容分类基础数据--人大金仓：`server/data/seed_ywnrfl_gjsjsf_1_kingbase.sql`
- 业务内容分类基础数据--高斯：`server/data/seed_ywnrfl_gjsjsf_1_gauss.sql`

### 5. 重点注意事项

- 改造点 `3` 的 `zdybm` 唯一索引创建前，需先检查历史数据是否有重复非空编码，否则升级脚本可能执行失败。
- 改造点 `4` 的 `ywblfl` 默认值建议统一为 `1`，升级后需确认历史空值是否已补齐。
- 改造点 `2` 虽然建表脚本已包含 `gjj_ywnrfl`，但业务可用还依赖分类基础数据初始化。
- 改造点 `6` 属于存储过程层改造，不能只执行表结构脚本，需要配套执行过程/函数脚本。
- 改造点 `8` 按仓库当前 SQL 实现，已在升级脚本中补充 `gjj_ywbz.ywbzz` 字段，现场应以实际脚本为准。
- 改造点 `12` 不新增业务标准专用表，但依赖现有 AI 工作流配置能力，需提前确认 `sys_dify_config` 及页面级配置链路可用。
-  已部署的环境，更新程序后需要在 `运维服务商` ->`公积金关键数据计算模型配置`->`页面管理` ->`关键数据计算模型` ->`编辑配置`->`下一步` ->`保存` （说明无需修改任何内容，仅用于页面样式更新）![](assets/关键数据算法260415更新说明/file-20260415171852264.png)
- 新建及已部署环境，启动程序后需要在`运维服务商` ->`公积金关键数据计算模型配置`->`页面管理` ->`关键数据计算模型` ->`AI 工作流`->`添加工作流` 或 `编辑` ->`确认`![](assets/关键数据算法260415更新说明/file-20260415171451015.png)![](assets/关键数据算法260415更新说明/file-20260415171744239.png)

## 五、升级实施步骤

### 1. 推荐实施顺序

建议现场统一按以下顺序实施：

1. 先备份当前生产 `docker-compose.yml`、`data/database.sqlite`、`config/datasources.json` 和相关业务表。
2. 先判断是“已上线旧库升级”还是“新环境初始化”，执行对应数据库主脚本。
3. 再执行改造点 `6` 的过程脚本及改造点 `2` 的基础数据脚本。
4. 核对数据库对象、字段和基础数据无误后，再更新程序镜像版本。
5. 最后按本说明的重点注意事项逐项执行。
