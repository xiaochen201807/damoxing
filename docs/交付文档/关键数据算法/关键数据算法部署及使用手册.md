## 一、手册说明

本手册面向实施人员、运维人员和交付人员，用于说明“关键数据算法”功能在现场环境中的部署、配置、数据库脚本执行、Dify 工作流配置、上线验证和回滚方法。

关键口径如下：

| 说明项   | 内容                                                                         |
| ----- | -------------------------------------------------------------------------- |
| 程序镜像  | 关键数据算法与程序规则控制管理使用同一个程序镜像                                                   |
| 镜像名称  | `damoxing`                                                                 |
| 部署方式  | 沿用《程序规则控制管理部署及使用手册》中的部署目录、`docker-compose.yml`、`.env` 和 `datasources.json` |
| 本手册重点 | 不重复展开通用容器部署，重点说明关键数据算法相关脚本、配置和验收                                           |
| 适用场景  | 新建环境部署、已上线环境升级、Dify/API 工作流接入和功能验收                                         |

> 注意：如果现场已经完成程序规则控制管理部署，通常不需要再部署一套新的关键数据算法服务。现场只需确认当前 `damoxing` 镜像版本满足关键数据算法交付要求，并完成本手册中的数据库脚本、页面配置和 AI 工作流配置。

## 二、与程序规则控制的部署关系

### 1. 共用镜像说明

程序规则控制和关键数据算法属于同一程序镜像中的两个业务能力，交付时应按同一个容器服务统一部署和升级。

| 能力 | 是否单独镜像 | 共用内容 | 差异内容 |
|----|----|----|----|
| 程序规则控制管理 | 否 | `damoxing` 镜像、部署目录、`docker-compose.yml`、`datasources.json` | 核心表为 `gjj_cxgzkz`，页面路径和初始化命令不同 |
| 关键数据算法 | 否 | `damoxing` 镜像、部署目录、`docker-compose.yml`、`datasources.json` | 依赖业务标准相关脚本、存储过程、分类基础数据和 AI 工作流配置 |

### 2. 部署文档分工

| 文档 | 主要用途 | 本手册引用方式 |
|----|----|----|
| 《程序规则控制管理部署及使用手册》 | 说明通用程序部署、镜像启动、数据源配置、容器检查和程序规则控制初始化 | 作为共用镜像和基础部署说明 |
| 《关键数据算法260415更新说明》 | 说明关键数据算法公版更新内容、脚本清单、镜像版本和升级注意事项 | 作为版本更新和脚本执行依据 |
| 《Dify 使用说明》 | 说明 Dify 账号、工作流导入、API Key 和内嵌地址获取方式 | 作为 AI 工作流配置依据 |
| 本手册 | 汇总关键数据算法部署操作闭环 | 用于现场按步骤实施和验收 |

### 3. 推荐交付口径

现场交付时建议统一说明：

1. 关键数据算法不单独提供新的服务名称或单独容器。
2. 关键数据算法和程序规则控制均运行在 `damoxing` 镜像对应的服务中。
3. 如果现场已经部署旧版 `damoxing`，本次只需要按最终交付 tag 升级镜像。
4. 镜像升级前先备份配置文件和业务库对象。
5. 镜像升级后再完成页面配置刷新、AI 工作流配置和业务验收。

## 四、部署前准备

### 1. 基础环境确认

| 检查项 | 说明 |
|----|----|
| 基础容器部署 | 确认 `damoxing` 服务部署目录、编排文件和数据目录已准备 |
| 镜像版本 | 确认当前镜像 tag 是否满足关键数据算法交付要求 |
| 数据库类型 | 确认现场业务库类型：Oracle、达梦、PostgreSQL、GaussDB 或人大金仓 |
| 数据库权限 | 确认账号具备建表、改表、建索引、写入基础数据、创建或替换存储过程权限 |
| 数据源配置 | 确认 `config/datasources.json` 中机构路由和连接串正确 |
| Dify 环境 | 确认使用公司 Dify 或现场部署 Dify，并区分测试环境和生产环境 |
| 页面权限 | 确认操作账号具备页面管理、业务标准库配置保存和 AI 工作流配置权限 |

### 2. 部署目录

关键数据算法不需要独立部署目录，沿用 `damoxing` 共用部署目录，例如：

```text
/opt/damoxing/
  docker-compose.yml
  .env
  config/
    datasources.json
  data/
    database.sqlite
    logs/
    backups/
```

说明：源码仓库中的数据源配置模板位于 `server/config/datasources.json`；正式部署目录使用 `config/datasources.json`，并通过容器编排挂载到容器内 `/app/config/datasources.json`。

### 3. 备份要求

实施前至少备份以下内容：

| 备份项 | 建议方式 |
|----|----|
| 程序编排文件 | 备份当前 `docker-compose.yml` |
| 环境变量 | 备份 `.env` 或现场生产环境变量文件 |
| 数据源配置 | 备份 `config/datasources.json` |
| 系统库 | 备份 `data/database.sqlite` |
| 业务标准相关表 | 由 DBA 备份升级涉及表和索引 |
| 存储过程 | 由 DBA 导出现有过程或函数定义 |
| Dify 工作流 | 在 Dify 中导出当前工作流 DSL |

### 5. 推荐执行顺序

建议现场统一按以下顺序执行：

1. 备份程序配置、系统库、业务库表和存储过程。
2. 判断当前环境属于已上线旧库升级还是新建环境初始化。
3. 执行对应数据库的升级脚本或初始化脚本。
4. 执行关键数据算法存储过程脚本。
5. 执行业务内容分类基础数据脚本。
6. 核对新增表、字段、索引、存储过程和基础数据。
7. 再升级或重启 `damoxing` 程序镜像。

## 六、程序镜像部署或升级

### 1. 新建环境部署

如果现场尚未部署 `damoxing`，先按《程序规则控制管理部署及使用手册》完成基础部署：

1. 准备 `/opt/damoxing` 部署目录。
2. 放置 `docker-compose.yml`、`.env`、`config/datasources.json` 和系统库文件。
3. 校验并拉取最终交付镜像。
4. 启动容器并确认服务正常。
5. 再回到本手册执行关键数据算法数据库脚本和页面配置。

## 九、常见问题与处理建议

### 1. 页面打开后没有最新样式

处理建议：

1. 确认镜像 tag 已更新到最终交付版本。
2. 进入“页面管理 -> 关键数据计算模型 -> 编辑配置”。
3. 不修改内容，点击“下一步”并保存。
4. 清理浏览器缓存后重新访问页面。

### 2. 关键数据算法下拉没有新选项

处理建议：

1. 确认程序镜像版本是否正确。
2. 确认本地 JSON 配置是否随镜像更新。
3. 确认页面配置已重新保存。
4. 如涉及业务内容分类，检查 `gjj_ywnrfl` 基础数据是否已初始化。

### 3. 数据库脚本执行失败

处理建议：

1. 先停止继续执行后续脚本。
2. 核对数据库类型是否与脚本匹配。
3. 检查执行账号是否具备建表、改表、建索引和创建过程权限。
4. 对唯一索引创建失败场景，先检查历史数据是否存在重复非空编码。
5. 由 DBA 根据备份恢复或修正后再继续执行。

### 4. AI 工作流调用失败

处理建议：

1. 确认 Dify 工作流已发布。
2. 确认程序配置中的 API Key 为当前工作流最新密钥。
3. 确认 API 地址对应当前环境，测试和生产不可混用。
4. 从容器内检查到 Dify 地址的网络连通性。
5. 查看后端日志定位鉴权、超时或地址错误。

## 十、备份与回滚说明

### 1. 回滚场景

| 场景 | 回滚方式 |
|----|----|
| 程序镜像异常 | 将 `docker-compose.yml` 切回上一版镜像 tag，并重新 `docker compose up -d` |
| 配置文件异常 | 恢复备份的 `.env`、`config/datasources.json` 和 `data/database.sqlite` |
| 数据库结构异常 | 由 DBA 按现场规范回滚表结构、索引、过程和基础数据 |
| Dify 工作流异常 | 在 Dify 中导入升级前备份的 DSL |
| API 配置错误 | 恢复升级前记录的 API 地址和 API Key，或重新按 Dify 当前发布配置填写 |

### 2. 回滚注意事项

1. 回滚前先确认是否存在新增业务数据，避免直接覆盖造成数据丢失。
2. 数据库结构回滚应由 DBA 执行，不建议实施人员手工删除对象。
3. 如果只是不影响业务的页面配置问题，优先重新保存页面配置，不直接回滚镜像。
4. 如果是 Dify 调用异常，优先恢复 Dify 工作流和 API 配置，不直接回滚数据库。

## 十一、交付结论

关键数据算法部署应按“共用镜像、先库后程序、再配置、最后验收”的口径执行：

| 阶段 | 结论 |
|----|----|
| 共用镜像 | 程序规则控制和关键数据算法均使用 `damoxing` 镜像，不单独部署第二套服务 |
| 数据库 | 按已上线旧库或新建环境选择升级脚本或初始化脚本，并补充存储过程和分类基础数据 |
| 程序 | 使用最终交付 tag 升级同一个 `damoxing` 服务 |
| 页面 | 更新后需重新保存关键数据计算模型页面配置 |
| Dify | 涉及 AI 能力时，需导入或更新 Dify 工作流，并在程序中配置 API Key 和 API 地址 |
| 验收 | 同时完成容器、数据库对象、业务页面和 Dify 调用验证 |

如后续镜像 tag、digest、数据库脚本或 Dify 工作流有再次调整，仅需同步更新本手册中的版本信息、脚本清单、配置路径和修订历史记录。
