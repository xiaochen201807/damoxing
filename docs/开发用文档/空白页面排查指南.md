# 空白页面问题排查指南

## 问题现象
- ✅ 容器启动成功
- ✅ 日志没有报错
- ❌ 浏览器访问显示空白页面

---

## 🔍 系统化排查步骤

### 步骤 1: 检查容器状态

```bash
# 1. 查看容器是否健康
docker ps
# 应该显示: STATUS = Up X minutes (healthy)

# 2. 如果显示 unhealthy，查看健康检查日志
docker inspect damoxing-app | grep -A 20 Health
```

**预期结果**: 容器状态应该是 `healthy`

---

### 步骤 2: 检查前端文件

```bash
# 进入容器
docker exec -it damoxing-app sh

# 检查前端文件是否存在
ls -la /usr/share/nginx/html/

# 应该看到:
# index.html
# assets/
# favicon.ico
# 等文件

# 查看 index.html 内容
cat /usr/share/nginx/html/index.html

# 检查文件大小（不应该是 0）
du -h /usr/share/nginx/html/index.html
```

**可能的问题**:
- ❌ 如果目录为空 → 前端构建失败或未包含在镜像中
- ❌ 如果 index.html 很小（< 1KB）→ 可能是空文件

---

### 步骤 3: 检查 Nginx 配置和日志

```bash
# 在容器内执行

# 1. 测试 Nginx 配置
nginx -t

# 2. 查看 Nginx 访问日志
tail -f /var/log/nginx/access.log

# 3. 查看 Nginx 错误日志
cat /var/log/nginx/error.log

# 4. 检查 Nginx 是否运行
ps aux | grep nginx
```

**同时在浏览器访问**，观察日志输出。

**预期日志**:
```
192.168.1.100 - - [17/Dec/2023:11:44:35 +0800] "GET / HTTP/1.1" 200 1234
192.168.1.100 - - [17/Dec/2023:11:44:35 +0800] "GET /assets/index-abc123.js HTTP/1.1" 200 56789
```

**问题日志**:
```
# 404 错误 - 文件不存在
"GET / HTTP/1.1" 404

# 403 错误 - 权限问题
"GET / HTTP/1.1" 403

# 500 错误 - 服务器错误
"GET / HTTP/1.1" 500
```

---

### 步骤 4: 检查后端 API

```bash
# 在容器内执行

# 1. 检查后端是否运行
ps aux | grep node

# 2. 检查端口监听
netstat -tuln | grep 3001
# 或
ss -tuln | grep 3001

# 3. 测试健康检查端点
wget -O- http://127.0.0.1:3001/health

# 4. 测试菜单 API
wget -O- http://127.0.0.1:3001/api/system/menu
```

**预期结果**:
```json
{"status":0,"msg":"success","data":[...]}
```

---

### 步骤 5: 检查数据库

```bash
# 在容器内执行

# 1. 检查数据库文件是否存在
ls -lh /app/data/database.sqlite

# 2. 检查数据库是否有数据
sqlite3 /app/data/database.sqlite ".tables"

# 应该看到:
# sys_dify_config  sys_menu  sys_page_template

# 3. 检查菜单数据
sqlite3 /app/data/database.sqlite "SELECT * FROM sys_menu;"

# 4. 检查页面模板数据
sqlite3 /app/data/database.sqlite "SELECT page_key, title FROM sys_page_template WHERE is_active=1;"
```

**可能的问题**:
- ❌ 数据库文件不存在 → 初始化失败
- ❌ 表不存在 → 数据库结构错误
- ❌ 数据为空 → 需要导入初始数据

---

### 步骤 6: 浏览器开发者工具检查

在浏览器中按 `F12` 打开开发者工具：

#### 6.1 Network 标签

查看网络请求：

**正常情况**:
```
✅ GET / → 200 OK (HTML)
✅ GET /assets/index-abc123.js → 200 OK
✅ GET /assets/index-def456.css → 200 OK
✅ GET /api/system/menu → 200 OK
```

**问题情况**:
```
❌ GET / → 404 Not Found
   → 前端文件不存在

❌ GET /assets/index-abc123.js → 404 Not Found
   → 资源文件缺失

❌ GET /api/system/menu → 404 Not Found
   → 后端 API 路由问题

❌ GET /api/system/menu → 500 Internal Server Error
   → 后端错误（检查数据库）

❌ 没有任何 /api 请求
   → 前端 API 配置错误（VITE_API_BASE_URL）
```

#### 6.2 Console 标签

查看 JavaScript 错误：

**常见错误**:
```javascript
// 1. 资源加载失败
Failed to load resource: net::ERR_FILE_NOT_FOUND

// 2. API 请求失败
Failed to fetch

// 3. CORS 错误
Access to fetch at 'http://...' has been blocked by CORS policy

// 4. JavaScript 错误
Uncaught TypeError: Cannot read property 'xxx' of undefined
```

#### 6.3 Application 标签

检查存储：
- Local Storage
- Session Storage
- Cookies

## 🎯 常见问题和解决方案

### 问题 1: 前端文件缺失

**症状**:
- `/usr/share/nginx/html/` 目录为空或只有少量文件
- 浏览器显示 404 或空白页

**原因**:
- 镜像构建时前端构建失败
- Dockerfile COPY 路径错误

**解决方案**:
```bash
# 检查镜像构建日志
# 在 GitHub Actions 中查看构建日志，确认前端构建成功

# 临时解决：手动复制前端文件
docker cp ./client/dist/. damoxing-app:/usr/share/nginx/html/
docker exec damoxing-app nginx -s reload
```

---

### 问题 2: 数据库未初始化

**症状**:
- API 返回空数据或错误
- 数据库文件不存在或为空

**原因**:
- 首次启动时数据库模板未正确复制
- 卷挂载路径错误

**解决方案**:
```bash
# 1. 停止容器
docker-compose down

# 2. 检查宿主机数据目录
ls -la ./data/

# 3. 如果数据库不存在，从开发环境复制
cp server/database.sqlite data/database.sqlite

# 4. 重启容器
docker-compose up -d

# 5. 查看初始化日志
docker logs damoxing-app | grep Init
```

---

### 问题 3: API 基础路径配置错误

**症状**:
- 浏览器 Network 中没有 `/api` 请求
- Console 显示请求到错误的域名

**原因**:
- 镜像构建时使用了错误的 `VITE_API_BASE_URL`

**检查方法**:
```bash
# 在容器内检查前端构建产物
docker exec -it damoxing-app sh
cat /usr/share/nginx/html/assets/index-*.js | grep -o 'http[s]*://[^"]*' | head -5

# 如果看到类似 https://api.yourdomain.com，说明配置错误
```

**解决方案**:
```bash
# 需要重新构建镜像，确保 .env.production 正确
# client/.env.production
VITE_API_BASE_URL=

# 然后推送代码触发重新构建
```

---

### 问题 4: CORS 配置问题

**症状**:
- 浏览器 Console 显示 CORS 错误
- API 请求被阻止

**原因**:
- `CORS_ORIGIN` 配置不匹配访问域名

**解决方案**:
```bash
# 方法 1: 修改 docker-compose.yml
environment:
  - CORS_ORIGIN=*  # 允许所有来源（开发环境）

# 方法 2: 指定具体域名
environment:
  - CORS_ORIGIN=http://your-domain.com,http://192.168.1.100

# 重启容器
docker-compose up -d
```

---

### 问题 5: Nginx 配置错误

**症状**:
- Nginx 错误日志有报错
- 页面返回 502 Bad Gateway

**检查**:
```bash
docker exec -it damoxing-app nginx -t
docker exec -it damoxing-app cat /var/log/nginx/error.log
```

**常见错误**:
```
# 后端连接失败
connect() failed (111: Connection refused) while connecting to upstream

# 解决：检查后端是否运行在 3001 端口
ps aux | grep node
netstat -tuln | grep 3001
```

## 📋 快速诊断脚本

将以下脚本保存为 `diagnose.sh`，在服务器上运行：

```bash
#!/bin/bash
echo "========================================="
echo "大模型项目诊断脚本"
echo "========================================="

echo ""
echo "1. 容器状态:"
docker ps -a | grep damoxing

echo ""
echo "2. 健康检查:"
docker inspect damoxing-app | grep -A 5 '"Health"'

echo ""
echo "3. 前端文件:"
docker exec damoxing-app ls -lh /usr/share/nginx/html/ | head -10

echo ""
echo "4. 后端进程:"
docker exec damoxing-app ps aux | grep -E "nginx|node|supervisord"

echo ""
echo "5. 端口监听:"
docker exec damoxing-app netstat -tuln | grep -E "80|3001"

echo ""
echo "6. 数据库文件:"
docker exec damoxing-app ls -lh /app/data/

echo ""
echo "7. Nginx 错误日志 (最近10行):"
docker exec damoxing-app tail -10 /var/log/nginx/error.log

echo ""
echo "8. 测试健康检查:"
curl -s http://localhost/health

echo ""
echo "9. 测试菜单 API:"
curl -s http://localhost/api/system/menu | head -100

echo ""
echo "========================================="
echo "诊断完成"
echo "========================================="
```

运行：
```bash
chmod +x diagnose.sh
./diagnose.sh
```
