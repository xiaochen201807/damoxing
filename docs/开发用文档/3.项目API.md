# API 文档

## 概述

大模型系统提供 RESTful API 接口，支持用户认证、系统菜单、页面模板、路由管理、Dify 配置管理和 AI 生成等功能。

**Base URL**: `http://localhost:3001{API_ROUTE_PREFIX}`

> **注意**: `API_ROUTE_PREFIX` 为环境变量配置的 API 路径前缀，默认为 `/api`。生产环境可配置为如 `/gjjrgzn/api`。

## 认证机制

系统使用 **JWT (JSON Web Token)** 进行身份认证。

### 认证流程

1. 调用 `/api/auth/login` 接口获取 token
2. 在后续请求的 Header 中携带 token:
   ```
   Authorization: Bearer <token>
   ```

### 认证模式

系统支持两种认证模式（通过环境变量 `SKIP_LOCAL_AUTH` 控制）：

| 模式 | 环境变量 | 说明 |
|------|----------|------|
| 本地认证 | `SKIP_LOCAL_AUTH=false` | 使用本地用户名密码验证 |
| 网关单点登录 | `SKIP_LOCAL_AUTH=true` | 使用第三方网关 ticket 验证 |

### 无需认证的接口

以下接口无需携带 token：
- `/health` 及相关健康检查接口
- `/api/auth/login` 登录接口

## 健康检查 API

健康检查接口**无需认证**，用于容器编排和负载均衡。

### 1. 简单健康检查

**GET** `/health`

快速确认服务存活。

**响应示例**:
```json
{
  "status": "ok",
  "timestamp": "2026-01-23T00:00:00.000Z",
  "uptime": 12345.678
}
```

### 2. 详细健康检查

**GET** `/health/detailed`

检查所有关键依赖（数据库、缓存、内存、环境配置）。

**响应示例**:
```json
{
  "status": "healthy",
  "timestamp": "2026-01-23T00:00:00.000Z",
  "uptime": 12345.678,
  "checks": {
    "database": { "status": "healthy", "message": "Database connection OK" },
    "cache": { "status": "healthy", "stats": { "totalKeys": 10 } },
    "memory": { "status": "healthy", "heapUsagePercent": 45 },
    "environment": { "status": "healthy", "hasDifyKey": true }
  },
  "process": {
    "pid": 12345,
    "nodeVersion": "v18.19.0",
    "platform": "darwin"
  }
}
```

### 3. 就绪检查

**GET** `/health/ready`

检查服务是否准备好接收流量（Kubernetes readinessProbe）。

### 4. 存活检查

**GET** `/health/alive`

最轻量的存活检查（Kubernetes livenessProbe）。

## 用户认证 API

### 1. 用户登录

**POST** `/api/auth/login`

**请求体（本地认证模式）**:
```json
{
  "username": "admin",
  "password": "password123"
}
```

**请求体（网关单点登录模式）**:
```json
{
  "ticket": "gateway-ticket",
  "tyLoginToken": "gateway-login-token",
  "qycode": "企业代码"
}
```

**响应示例**:
```json
{
  "status": 0,
  "msg": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": 1,
      "username": "admin",
      "nickname": "管理员",
      "role": "admin"
    }
  }
}
```

### 2. 获取当前用户信息

**GET** `/api/auth/current`

需要携带 Authorization 头。

**响应示例**:
```json
{
  "status": 0,
  "msg": "success",
  "data": {
    "id": 1,
    "username": "admin",
    "nickname": "管理员",
    "role": "admin"
  }
}
```

## 系统菜单 API

### 1. 获取系统菜单

**GET** `/api/system/menu`

获取所有系统菜单项（支持多级菜单）。

**查询参数**:
- `route_key` (可选): 按路由组筛选

**响应示例**:
```json
{
  "status": 0,
  "msg": "success",
  "data": [
    {
      "id": 1,
      "label": "贷款风险分析",
      "subtitle": "实时监控贷款风险指标",
      "page_key": "loan_risk",
      "path": "/dashboard/loan_risk",
      "icon": "fa fa-chart-line",
      "route_key": "dashboard",
      "order": 1,
      "parent_id": null,
      "is_active": 1
    }
  ]
}
```

### 2. 创建菜单

**POST** `/api/system/menu`

**请求体**:
```json
{
  "label": "客户分析",
  "subtitle": "客户行为分析与画像",
  "page_key": "customer_analysis",
  "path": "/dashboard/customer_analysis",
  "icon": "fa fa-users",
  "route_key": "dashboard",
  "order": 10,
  "parent_id": null
}
```

### 3. 更新菜单

**POST** `/api/system/menu/:pageKey`

**请求体**（所有字段可选）:
```json
{
  "label": "新菜单名称",
  "subtitle": "新副标题",
  "icon": "fa fa-new-icon",
  "order": 5,
  "is_active": 1
}
```

### 4. 删除菜单

**POST** `/api/system/menu/delete`

**请求体**:
```json
{
  "ids": [1, 2, 3]
}
```

### 7. 获取页面备份版本

**GET** `/api/system/template/:pageKey/backups`

### 8. 恢复页面版本

**POST** `/api/system/template/:pageKey/restore`

**请求体**:

**GET** `/api/system/template-definitions`

获取所有可用的页面模板定义。

## Dify 配置管理 API

### 1. 获取所有配置

**GET** `/api/dify/config`

**响应示例**:
```json
{
  "status": 0,
  "msg": "success",
  "data": [
    {
      "id": 1,
      "page_key": "loan_risk",
      "workflow_name": "贷款风险分析",
      "workflow_type": "ai_analysis",
      "api_url": "https://api.dify.ai/v1",
      "api_key": "app-xxx",
      "enabled": 1,
      "description": "贷款风险分析工作流",
      "created_at": "2026-01-01 00:00:00",
      "updated_at": "2026-01-01 00:00:00"
    }
  ]
}
```

### 2. 获取指定配置

**GET** `/api/dify/config/:id`

**路径参数**:
- `id` (number): 配置 ID

### 3. 创建配置

**POST** `/api/dify/config`

**请求体**:
```json
{
  "page_key": "dashboard",
  "workflow_name": "数据分析工作流",
  "workflow_type": "ai_analysis",
  "api_url": "https://api.dify.ai/v1",
  "api_key": "app-xxx",
  "enabled": 1,
  "description": "可选描述"
}
```

**参数验证**:
| 字段 | 必填 | 说明 |
|------|------|------|
| `page_key` | ✅ | 字母数字，1-50字符 |
| `workflow_name` | ✅ | 1-100字符 |
| `workflow_type` | ❌ | 默认 `ai_analysis` |
| `api_url` | ✅ | 有效的 URL |
| `api_key` | ✅ | 1-500字符 |
| `enabled` | ❌ | 0 或 1，默认 1 |
| `description` | ❌ | 最多 500 字符 |

### 4. 更新配置

**POST** `/api/dify/config/:id`

**请求体**（所有字段可选，至少一个）:
```json
{
  "workflow_name": "新工作流名称",
  "api_url": "https://api.dify.ai/v1",
  "api_key": "app-new-key",
  "enabled": 0,
  "description": "更新描述"
}
```

## AI 生成 API

### 1. 生成内容（Chat Messages）

**POST** `/api/ai/generate`

**限流**: 1分钟10次

**请求体**:
```json
{
  "query": "生成一个贷款风险分析页面",
  "pageId": "loan_risk"
}
```

**参数**:
| 字段 | 必填 | 说明 |
|------|------|------|
| `query` | ✅ | 1-2000字符 |
| `pageId` | ❌ | 字母数字，最多50字符 |

**响应示例**:
```json
{
  "status": 0,
  "msg": "success",
  "data": {
    "type": "page",
    "title": "AI 生成页面",
    "body": [ ... ]
  },
  "cached": false
}
```

### 2. 生成页面（Workflow）

**POST** `/api/ai/generate-page`

**限流**: 1分钟10次

**请求体**:
```json
{
  "query": "生成贷款风险分析页面，包含KPI和图表",
  "pageId": "loan_risk"
}
```

**配置优先级**:
1. 数据库中 `pageId` 对应的配置
2. 环境变量 `DIFY_API_KEY`
3. Mock 数据（如果都未配置）

## 错误码

| 状态码 | 说明 |
|--------|------|
| 0 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证/Token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 资源冲突（如重复创建） |
| 429 | 请求过于频繁 |
| 500 | 服务器内部错误 |

---

## 限流规则

| 接口类型 | 时间窗口 | 最大请求数 |
|----------|----------|------------|
| 全局限流 | 15分钟 | 100次 |
| AI 接口 | 1分钟 | 10次 |

超过限制返回 429 状态码。

> **提示**: 限流参数可通过 `sys_backend_config` 表配置修改。

## 使用示例

### cURL 示例

```bash
# 1. 登录获取 token
curl -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "password123"}'

# 保存返回的 token
TOKEN="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

# 2. 获取菜单（需要认证）
curl http://localhost:3001/api/system/menu \
  -H "Authorization: Bearer $TOKEN"

# 3. 获取页面模板
curl http://localhost:3001/api/page/loan_risk \
  -H "Authorization: Bearer $TOKEN"

# 4. 创建 Dify 配置
curl -X POST http://localhost:3001/api/dify/config \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "page_key": "dashboard",
    "workflow_name": "数据分析",
    "api_url": "https://api.dify.ai/v1",
    "api_key": "app-xxx"
  }'

# 5. AI 生成
curl -X POST http://localhost:3001/api/ai/generate \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "query": "生成风险分析页面",
    "pageId": "loan_risk"
  }'

# 6. 健康检查（无需认证）
curl http://localhost:3001/health
curl http://localhost:3001/health/detailed
```

### JavaScript 示例

```javascript
// 登录
const loginResponse = await fetch('http://localhost:3001/api/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    username: 'admin',
    password: 'password123'
  })
});
const { data: { token } } = await loginResponse.json();

// 保存 token 到 localStorage
localStorage.setItem('auth_token', token);

// 带认证的请求
const menuResponse = await fetch('http://localhost:3001/api/system/menu', {
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  }
});
const menuData = await menuResponse.json();
console.log(menuData);

// 创建 Dify 配置
const configResponse = await fetch('http://localhost:3001/api/dify/config', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    page_key: 'dashboard',
    workflow_name: '数据分析',
    api_url: 'https://api.dify.ai/v1',
    api_key: 'app-xxx'
  })
});
```

## 安全建议

1. **使用 HTTPS** - 生产环境必须使用 HTTPS
2. **妥善保管 Token** - 不要在 URL 中传递 Token
3. **定期更换密钥** - 定期更换 JWT 密钥和 API Key
4. **输入验证** - 所有输入已通过 Joi 验证
5. **限流防护** - 已配置全局和 AI 接口限流
6. **SQL 注入防护** - 使用参数化查询
