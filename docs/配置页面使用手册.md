## 概述

大模型系统提供了完善的配置管理功能,支持通过可视化界面管理系统的各项配置。本手册将详细介绍各个配置页面的使用方法。

### 配置页面入口

系统配置功能通常位于系统菜单中,包括以下几个主要模块:

- **菜单管理** - 管理系统导航菜单
- **页面模板管理** - 管理页面的 AMIS Schema 模板
- **AI 工作流配置** - 配置 Dify AI 工作流
- **后端配置** - 管理系统后端参数(如 API 限流)

## 菜单管理

### 功能说明

菜单管理用于创建、编辑和删除系统的导航菜单项。每个菜单项对应一个页面,通过 `page_key` 关联到页面模板和 AI 工作流。

### 字段说明

| 字段名 | 说明 | 是否必填 | 格式要求 |
|--------|------|----------|----------|
| **菜单名称** (`label`) | 显示在导航栏的菜单名称 | ✅ 必填 | 任意文本 |
| **副标题** (`subtitle`) | 菜单的辅助说明文字 | ❌ 可选 | 任意文本 |
| **页面标识** (`page_key`) | 页面的唯一标识符 | ✅ 必填 | 只能包含字母、数字、下划线和连字符 |
| **图标** (`icon`) | 菜单图标 | ❌ 可选 | 图标名称或 URL |

### 操作指南

#### 1. 创建菜单

1. 点击**"新增菜单"**按钮
2. 填写菜单信息:
   - **菜单名称**: 例如 `贷款风险分析`
   - **副标题**: 例如 `实时监控贷款风险指标`
   - **页面标识**: 例如 `loan_risk` (系统会自动生成路径 `/dashboard/loan_risk`)
   - **图标**: 可选,例如 `fa fa-chart-line`
3. 点击**"提交"**保存

> **💡 提示**: `page_key` 必须唯一,不能与现有菜单重复。创建后系统会自动生成访问路径。

#### 2. 编辑菜单

1. 在菜单列表中找到要编辑的菜单
2. 点击**"编辑"**按钮
3. 修改需要更新的字段
4. 点击**"提交"**保存

> **⚠️ 注意**: 修改 `page_key` 会同时更新访问路径,请谨慎操作。

#### 3. 删除菜单

1. 在菜单列表中找到要删除的菜单
2. 点击**"删除"**按钮
3. 确认删除操作

> **⚠️ 警告**: 删除菜单不会删除关联的页面模板和 AI 工作流配置,但用户将无法通过导航访问该页面。

### 最佳实践

- **命名规范**: 使用清晰、简洁的菜单名称,避免过长
- **page_key 规范**: 建议使用小写字母和下划线,例如 `loan_risk`、`customer_analysis`
- **图标选择**: 使用 Font Awesome 图标库,例如 `fa fa-dashboard`、`fa fa-chart-bar`

## 页面模板管理

### 功能说明

页面模板管理用于创建和维护页面的 AMIS Schema。每个页面模板通过 `page_key` 与菜单关联,支持版本管理和备份。

### 字段说明

| 字段名 | 说明 | 是否必填 | 格式要求 |
|--------|------|----------|----------|
| **关联菜单** | 选择要关联的菜单项 | ✅ 必填 | 从下拉列表选择 |
| **页面标识** (`page_key`) | 自动填充,来自关联菜单 | ✅ 必填 | 自动生成 |
| **页面标题** (`title`) | 页面显示标题 | ✅ 必填 | 任意文本 |
| **Schema** | AMIS 页面配置 JSON | ✅ 必填 | 有效的 JSON 格式 |
| **版本号** (`version`) | 模板版本 | ✅ 必填 | 整数,默认为 1 |
| **是否激活** (`is_active`) | 是否为当前使用版本 | ✅ 必填 | 1=激活, 0=备份 |

### 操作指南

#### 1. 创建页面模板

1. 点击**"新增页面模板"**按钮
2. 选择**关联菜单** - 系统会自动填充 `page_key` 和 `title`
3. 编辑 **Schema** - 输入 AMIS 页面配置 JSON
4. 设置**版本号** - 默认为 1
5. 勾选**是否激活** - 新模板通常设为激活状态
6. 点击**"提交"**保存

**Schema 示例**:
```json
{
  "type": "page",
  "title": "贷款风险分析",
  "body": [
    {
      "type": "chart",
      "config": {
        "title": { "text": "风险分布" },
        "series": [
          {
            "type": "pie",
            "data": [
              { "name": "高风险", "value": 30 },
              { "name": "中风险", "value": 50 },
              { "name": "低风险", "value": 20 }
            ]
          }
        ]
      }
    }
  ]
}
```

#### 2. 编辑页面模板

1. 在模板列表中找到要编辑的模板
2. 点击**"编辑"**按钮
3. 修改 Schema 或其他字段
4. 点击**"提交"**保存

> **💡 提示**: 编辑模板时,建议先创建备份版本,避免直接修改激活版本。

#### 3. 版本管理

系统支持为每个页面保留多个版本:

- **激活版本** (`is_active=1`): 当前用户访问时使用的版本
- **备份版本** (`is_active=0`): 历史版本,可用于回滚

**创建备份版本**:
1. 复制现有模板的 Schema
2. 创建新模板,使用相同的 `page_key`
3. 设置新的 `version` 号(递增)
4. 将 `is_active` 设为 0

**激活备份版本**:
1. 编辑要激活的备份版本
2. 将 `is_active` 改为 1
3. 同时将旧的激活版本改为 0

#### 4. 删除页面模板

1. 在模板列表中找到要删除的模板
2. 点击**"删除"**按钮
3. 确认删除操作

> **⚠️ 注意**: 删除操作为软删除,实际上是将 `is_active` 设为 0。

### 最佳实践

- **Schema 验证**: 提交前使用 JSON 验证工具检查格式
- **版本控制**: 重大更新前创建备份版本
- **命名规范**: 页面标题应与菜单名称保持一致
- **测试流程**: 在测试环境验证 Schema 后再部署到生产环境

## AI 工作流配置

### 功能说明

AI 工作流配置用于为每个页面配置独立的 Dify AI 工作流。系统支持通过 AI 分析用户输入并生成动态内容。

### 字段说明

| 字段名 | 说明 | 是否必填 | 格式要求 |
|--------|------|----------|----------|
| **关联页面模板** | 选择要关联的页面 | ✅ 必填 | 从下拉列表选择 |
| **页面标识** (`page_key`) | 自动填充,来自关联页面 | ✅ 必填 | 自动生成 |
| **工作流名称** (`workflow_name`) | Dify 工作流的名称 | ✅ 必填 | 任意文本 |
| **API 地址** (`api_url`) | Dify API 端点 | ✅ 必填 | 有效的 URL |
| **API 密钥** (`api_key`) | Dify API Key | ✅ 必填 | 以 `app-` 开头 |
| **是否启用** (`enabled`) | 是否启用该工作流 | ✅ 必填 | 1=启用, 0=禁用 |
| **描述** (`description`) | 工作流说明 | ❌ 可选 | 任意文本 |

### 操作指南

#### 1. 创建 AI 工作流配置

1. 点击**"新增配置"**按钮
2. 选择**关联页面模板** - 系统会自动填充 `page_key`
3. 填写**工作流名称** - 例如 `贷款风险分析工作流`
4. 填写 **API 地址** - 例如 `https://api.dify.ai/v1`
5. 填写 **API 密钥** - 从 Dify 平台获取,格式如 `app-xxxxxxxx`
6. 勾选**是否启用**
7. 填写**描述**(可选)
8. 点击**"提交"**保存

#### 2. 编辑 AI 工作流配置

1. 在配置列表中找到要编辑的配置
2. 点击**"编辑"**按钮
3. 修改需要更新的字段
4. 点击**"提交"**保存

> **💡 提示**: 修改 API 密钥后,需要重新测试工作流是否正常工作。

#### 3. 启用/禁用工作流

- **启用**: 将 `enabled` 设为 1,页面将调用 AI 工作流
- **禁用**: 将 `enabled` 设为 0,页面将不调用 AI 工作流

#### 4. 删除 AI 工作流配置

1. 在配置列表中找到要删除的配置
2. 点击**"删除"**按钮
3. 确认删除操作

> **⚠️ 注意**: 删除配置后,对应页面将无法使用 AI 功能。

### 获取 Dify API 密钥

1. 登录 [Dify 平台](https://dify.ai)
2. 进入工作流管理页面
3. 创建或选择一个工作流
4. 在工作流设置中找到 **API 密钥**
5. 复制密钥(格式: `app-xxxxxxxxxxxxxxxx`)

### 最佳实践

- **密钥安全**: 不要在前端代码中硬编码 API 密钥
- **工作流测试**: 配置完成后,在页面中测试 AI 功能是否正常
- **错误处理**: 配置错误的 API 地址或密钥会导致 AI 功能失效
- **环境隔离**: 开发和生产环境使用不同的 API 密钥

## 后端配置管理

### 功能说明

后端配置管理用于调整系统后端参数,如 API 限流设置。修改这些配置通常需要重启服务器才能生效。

### 配置项说明

| 配置键 | 说明 | 类型 | 默认值 | 有效范围 |
|--------|------|------|--------|----------|
| **global_rate_limit_window** | 全局限流时间窗口(毫秒) | 数字 | 900000 (15分钟) | 1000 - 3600000 |
| **global_rate_limit_max** | 全局限流最大请求数 | 数字 | 100 | 1 - 10000 |
| **ai_rate_limit_window** | AI 限流时间窗口(毫秒) | 数字 | 60000 (1分钟) | 1000 - 3600000 |
| **ai_rate_limit_max** | AI 限流最大请求数 | 数字 | 10 | 1 - 10000 |

### 操作指南

#### 1. 查看后端配置

1. 进入**后端配置管理**页面
2. 查看当前所有配置项及其值

#### 2. 修改配置

1. 在配置列表中找到要修改的配置项
2. 点击**"编辑"**按钮
3. 输入新的配置值
4. 点击**"提交"**保存

> **⚠️ 重要**: 修改配置后需要重启服务器才能生效!

#### 3. 重启服务器

**Docker 部署**:
```bash
docker-compose restart
```

**传统部署**:
```bash
pm2 restart damoxing-api
```

### 配置建议

#### 全局限流配置

- **低流量场景** (内部系统):
  - `global_rate_limit_window`: 900000 (15分钟)
  - `global_rate_limit_max`: 100

- **中等流量场景**:
  - `global_rate_limit_window`: 900000 (15分钟)
  - `global_rate_limit_max`: 500

- **高流量场景**:
  - `global_rate_limit_window`: 900000 (15分钟)
  - `global_rate_limit_max`: 1000

#### AI 限流配置

由于 AI 接口调用成本较高,建议保持较严格的限流:

- **开发/测试环境**:
  - `ai_rate_limit_window`: 60000 (1分钟)
  - `ai_rate_limit_max`: 20

- **生产环境**:
  - `ai_rate_limit_window`: 60000 (1分钟)
  - `ai_rate_limit_max`: 10

### 最佳实践

- **监控流量**: 根据实际流量调整限流参数
- **逐步调整**: 不要一次性大幅修改配置值
- **备份配置**: 修改前记录原始配置值
- **测试验证**: 修改后测试系统是否正常工作

## 常见问题

### Q1: 创建菜单时提示 "page_key 已存在" 怎么办?

**原因**: `page_key` 必须唯一,不能与现有菜单重复。

**解决方案**:
1. 检查是否已存在相同的 `page_key`
2. 使用不同的 `page_key`,例如添加后缀 `_v2`
3. 如果是要替换旧菜单,先删除旧菜单再创建新菜单

### Q2: 页面模板的 Schema 格式错误怎么办?

**原因**: Schema 必须是有效的 JSON 格式。

**解决方案**:
1. 使用 JSON 验证工具检查格式(例如 [JSONLint](https://jsonlint.com))
2. 检查是否有缺失的逗号、括号或引号
3. 参考 [AMIS 官方文档](https://aisuda.bce.baidu.com/amis/zh-CN/docs/index) 学习正确的 Schema 格式

### Q3: AI 工作流配置后不生效?

**可能原因**:
1. API 密钥错误或已过期
2. API 地址配置错误
3. 工作流未启用 (`enabled=0`)
4. Dify 工作流本身配置有问题

**解决方案**:
1. 检查 API 密钥是否正确,格式是否为 `app-xxxxxxxx`
2. 验证 API 地址是否可访问
3. 确认 `enabled` 字段为 1
4. 在 Dify 平台测试工作流是否正常
5. 查看服务器日志排查错误

### Q4: 修改后端配置后没有生效?

**原因**: 后端配置需要重启服务器才能生效。

**解决方案**:
```bash
# Docker 部署
docker-compose restart

# 传统部署
pm2 restart damoxing-api
```

### Q5: 如何备份页面模板?

**方案 1: 使用版本管理**
1. 创建新版本的模板
2. 将 `is_active` 设为 0
3. 保留旧版本作为备份

**方案 2: 导出 Schema**
1. 复制 Schema JSON 内容
2. 保存到本地文件
3. 需要时重新导入

### Q6: 删除菜单后页面还能访问吗?

**回答**: 
- 删除菜单只是移除了导航入口
- 页面模板和 AI 工作流配置仍然存在
- 如果知道页面路径(例如 `/dashboard/loan_risk`),仍可直接访问
- 要完全移除页面,需要同时删除菜单、页面模板和 AI 工作流配置

### Q7: 如何批量管理配置?

**建议**:
1. 使用 API 接口批量操作(参考 [API 文档](./API.md))
2. 直接操作数据库(需谨慎,建议先备份)
3. 编写脚本自动化配置管理

### Q8: 配置数据存储在哪里?

**存储位置**:
- **Docker 部署**: `./data/database.sqlite`
- **传统部署**: `./server/database.sqlite`

**备份方法**:
```bash
# Docker 部署
docker-compose exec app npm run db:backup

# 传统部署
cd server
npm run db:backup
```
