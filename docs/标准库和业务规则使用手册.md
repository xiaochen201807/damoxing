# 标准库和业务规则使用手册

## 1. 手册说明

本手册面向业务配置人员、实施人员、测试人员和运维人员，重点说明以下两部分功能的日常使用方法：

- 业务办理标准库
- 关键数据计算模型（业务规则）

本文档只讲怎么使用、怎么维护、数据存在哪里，不展开源码实现细节。

## 2. 功能关系总览

系统中的“标准库”和“业务规则”是两层结构。

| 模块 | 作用 | 适用范围 | 典型使用人 |
| --- | --- | --- | --- |
| 业务办理标准库 | 维护公共标准模板、属性定义、互斥关系、分类 | 通常作为模型机构统一维护 | 模型机构管理员、实施人员 |
| 关键数据计算模型（业务规则） | 基于标准库模板生成本机构规则，并配置具体参数值 | 按机构、子机构分别生效 | 机构配置人员、测试人员 |

可以把两者理解为：

- 标准库负责定义“有哪些标准、需要哪些参数、这些参数从哪里来”。
- 业务规则负责定义“本机构实际启用了哪些标准、具体参数值是多少、调试结果是否正确”。

## 3. 页面入口

页面路径可能因部署前缀不同而变化，常见入口如下：

- 标准库页面：`/gjj_gjsjjsmx/ywblbzk/main`
- 业务规则页面：`/gjj_gjsjjsmx/ywbz/ywbz`

如果现场系统做了统一菜单封装，以实际菜单名称为准：

- `业务办理标准库`
- `关键数据计算模型`

## 4. 使用前需要了解的规则

### 4.1 模型机构与非模型机构

标准库维护区分模型机构和非模型机构：

- 模型机构：可以新增、编辑、删除、维护业务内容分类。
- 非模型机构：标准库仅支持查看、全量导出、全量导入，不支持直接新增和修改。

这意味着：

- 公共模板建议由模型机构统一维护。
- 机构侧更多是在“业务规则”页面完成落地配置和调试。

### 4.2 推荐使用顺序

建议按下面顺序使用：

1. 先维护业务内容分类。
2. 再维护标准库模板、属性组和互斥关系。
3. 进入业务规则页面，通过“清册选择”把需要的标准同步到本机构。
4. 在“节点详细参数设置”中配置本机构的具体参数值。
5. 通过“调试”验证算法执行结果。
6. 完成后按需要做导出备份。

## 5. 业务办理标准库使用说明

### 5.1 页面作用

标准库页面用于维护关键算法下的标准模板，主要包括：

- 业务内容分类
- 业务办理标准模板
- 标准属性组
- 标准互斥关系
- 全量导入和全量导出

标准库更偏向“模板定义”，不是直接给某个机构填参数结果的页面。

### 5.2 页面主要查询条件

主页面常用查询项包括：

- 关键数据算法
- 业务内容分类
- 业务办理标准

适用场景：

- 想看某个算法下配置了哪些标准
- 想筛选某类业务内容下的模板
- 想通过标准名称快速定位一条模板

### 5.3 业务内容分类维护

“业务内容分类维护”用于维护某个关键数据算法下的业务场景分类，例如购房、租房、还贷、离退休等。

常见操作：

1. 选择关键数据算法。
2. 维护分类编码。
3. 维护分类名称。
4. 设置排序号。
5. 选择是否启用。

使用建议：

- 同一关键数据算法下，分类编码不能重复。
- 分类编码一旦投入使用，不建议频繁修改。
- 如果某分类已经被标准库或业务规则引用，通常不能直接删除。

分类维护完成后：

- 标准库页面的“业务内容分类”下拉会使用这份数据。
- 业务规则页面按算法筛选时，也会使用同一份分类数据。

### 5.4 新增或编辑标准模板

标准模板是标准库的核心内容。每条模板通常包括以下信息。

#### 5.4.1 基本信息

常见字段说明如下：

| 字段 | 说明 | 使用建议 |
| --- | --- | --- |
| 排序号 | 控制展示顺序 | 建议按业务阅读顺序维护 |
| 业务办理标准 | 标准名称 | 建议直观、可读 |
| 自定义编码 | 模板唯一业务编码 | 建议填写，便于对接、检索和迁移 |
| 业务办理标准描述 | 对标准用途的文字说明 | 建议写清楚适用场景 |
| 关键数据算法 | 模板归属的算法 | 必填 |
| 业务内容分类 | 模板归属的业务场景 | 与算法配套使用 |
| 业务办理分类 | 区分“标准”或“条件” | 按实际业务选择 |
| 业务办理标准分类 | 用于归并同类标准 | 建议按业务口径统一维护 |
| 业务标准值 | 标准默认结果值 | 适合固定值类标准 |

其中：

- `自定义编码` 适合做外部识别码、初始化脚本识别码和跨环境对照码。
- `业务标准值` 更适合固定值、枚举值、阈值类标准。

#### 5.4.2 标准与条件

“业务办理分类”通常有两类：

- `标准`：用于返回某项业务标准结果。
- `条件`：用于判断某个条件是否成立。

使用上可以这样理解：

- 固定额度、倍数、精度、保留方式等，通常建成“标准”。
- 某项资格是否满足、某个场景是否命中，通常建成“条件”。

#### 5.4.3 结果语句

标准模板支持按数据库类型分别维护结果语句，例如：

- 默认数据库
- Oracle
- 达梦
- 高斯
- 人大金仓
- PostgreSQL

使用建议：

- 如果现场只用一种数据库，也建议至少维护“默认数据库”版本。
- 如果不同数据库语法差异明显，建议分别维护，避免跨库执行报错。
- 能用固定业务标准值表达的，优先用固定值；只有确实需要计算时，再维护语句。

#### 5.4.4 互斥业务办理标准

“互斥业务办理标准”表示这些模板不能在同一业务场景中同时生效。

适用场景：

- 同一业务场景下只能命中一种标准
- 不同口径的标准不能重复参与计算

维护原则：

- 互斥模板应属于同一关键数据算法、同一业务内容分类。
- 不要把自己设置成自己的互斥项。

#### 5.4.5 业务办理标准属性组

属性组用于定义这条标准需要哪些参数，后续业务规则页面会按这里的定义生成“节点详细参数设置”表单。

每个属性一般要维护以下内容：

| 字段 | 说明 |
| --- | --- |
| 业务办理标准属性所属对象 | 参数属于哪个业务对象 |
| 业务办理标准属性 | 具体参数项 |
| 属性来源 | 页面 / SQL |
| 业务办理标准属性来源执行语句 | 当来源为 SQL 时使用 |

使用建议：

- 如果参数由页面或接口直接传入，属性来源选“页面”。
- 如果参数需要从数据库查询或计算得出，属性来源选“SQL”。
- 属性名称建议统一口径，避免同义不同名。

### 5.5 标准库删除操作

删除标准模板前，建议先确认：

- 是否已经被业务规则引用
- 是否已经用于现场测试或生产口径
- 是否存在导出备份

如果模板已经在业务规则中被使用，直接删除可能导致引用异常，因此建议先停用使用方，再处理模板。

### 5.6 标准库导入导出

标准库页面支持：

- 全量导出
- 全量导入

#### 5.6.1 全量导出

适用场景：

- 环境迁移
- 上线前备份
- 模型机构向其他环境分发标准库

导出的内容通常包括：

- 业务内容分类
- 标准模板
- 属性组
- 互斥关系

#### 5.6.2 全量导入

适用场景：

- 初始化一套完整标准库
- 用标准环境覆盖目标环境

使用建议：

- 导入前先备份目标环境。
- 先确认文件来源可靠，再执行导入。
- 如果现场已经做过本地化调整，先评估是否会被覆盖。

### 5.7 标准库日常维护建议

- 先维护分类，再维护模板。
- 自定义编码建议从一开始就统一规范。
- 属性组尽量使用业务可理解的命名。
- 模板一旦被多个机构复用，修改前应先评估影响范围。

## 6. 关键数据计算模型（业务规则）使用说明

### 6.1 页面作用

业务规则页面面向机构配置，主要用于：

- 从标准库同步需要的模板
- 查看本机构已启用的规则
- 配置每个节点的具体参数值
- 调试算法执行结果
- 导入导出本机构规则

与标准库相比，业务规则更偏向“机构落地”和“参数配置”。

### 6.2 页面主要查询条件

主页面通常支持按以下条件筛选：

- 关键数据算法
- 业务内容分类

列表中常见列包括：

- 关键数据算法
- 业务内容分类
- 业务办理标准分类
- 业务办理标准
- 业务办理标准描述

### 6.3 清册选择

“清册选择”是业务规则页面最重要的入口之一，用于把标准库中的模板同步为本机构可配置的规则。

推荐操作步骤：

1. 先选择关键数据算法。
2. 如果算法要求区分业务内容分类，再选择业务内容分类。
3. 点击“清册选择”。
4. 在弹窗中勾选需要同步的业务办理标准。
5. 保存后回到主列表查看结果。

适用场景：

- 新机构初始化规则
- 某算法新增了标准模板后，同步到本机构
- 按业务内容分类补充某一批标准

使用建议：

- 清册选择前先确认标准库模板已经维护完整。
- 同步后应立即检查规则参数是否需要补充。
- 如果模板存在互斥关系，建议在勾选时一并核对。

### 6.4 节点详细参数设置

主列表中的“规则参数配置”会打开“节点详细参数设置”抽屉，用于配置该条规则的具体参数。

这是业务规则维护的核心环节。

#### 6.4.1 抽屉中可以看到什么

抽屉中通常会显示：

- 规则名称
- 标准模板名称
- 当前业务标准值
- 动态生成的参数录入区

如果该规则已经保存过参数，系统会优先反显已保存内容。

如果尚未保存参数，但标准模板上已经维护了“业务标准值”，抽屉中也会把当前值带出来，便于核对。

#### 6.4.2 如何理解“反显”

当前页面已经支持把规则的已保存值反显到“节点详细参数设置”中，重点体现在：

- 文本、数值、下拉等参数会按已保存值回填
- 结果列会显示当前业务标准值或已保存结果
- 再次打开同一条规则时，可以直接看到之前保存的具体值

这意味着：

- 配置人员不用每次重新填写
- 测试人员可以直接核对页面值是否与预期一致
- 修改参数后再次进入抽屉，可以确认是否已成功保存

#### 6.4.3 适合怎么维护

建议按下面方式使用：

1. 先确认抽屉顶部的“当前业务标准值”是否正确。
2. 按业务对象逐项填写参数。
3. 对多组参数场景，可新增多行。
4. 保存后重新打开抽屉，确认值是否正确反显。

适用场景示例：

- 同一规则存在多组适用条件
- 同一模板在不同机构下参数值不同
- 需要把页面传入值和结果值一起固化

### 6.5 业务规则删除

业务规则删除只影响当前机构、当前子机构下的该条规则，不影响标准库模板本身。

删除前建议确认：

- 是否仍有业务场景在使用
- 是否已经导出备份
- 是否会影响联调和回归测试

### 6.6 业务规则导入导出

业务规则页面支持四类操作：

- 全量导入
- 全量导出
- 部分导入
- 部分导出

#### 6.6.1 全量导出

适用场景：

- 对当前机构规则做完整备份
- 从测试环境提取一套完整规则
- 上线前留档

导出内容包括：

- 业务规则主数据
- 规则参数明细

#### 6.6.2 全量导入

适用场景：

- 初始化当前机构规则
- 用一套完整规则覆盖当前机构

使用建议：

- 导入前先确认导入文件对应的是目标机构要使用的模板集合。
- 建议先在测试环境验证，再导入正式环境。

#### 6.6.3 部分导出

适用场景：

- 只导出选中的规则
- 只迁移某一批模板对应的规则
- 提供给其他机构做增量同步

使用方式：

1. 先在列表中勾选需要导出的规则。
2. 点击“部分导出”。
3. 保存下载文件。

#### 6.6.4 部分导入

适用场景：

- 增量同步某一批规则
- 不影响未涉及模板的情况下补充新规则

使用建议：

- 部分导入更适合日常迭代。
- 导入后应立即抽查关键规则的参数和调试结果。

### 6.7 业务规则调试

调试用于验证当前算法、业务内容分类以及参数配置是否正确，是上线前必须执行的环节。

#### 6.7.1 调试前准备

建议先准备以下内容：

- 要验证的关键数据算法
- 需要验证的业务内容分类
- 一组可复现的业务入参
- 预期结果口径

#### 6.7.2 调试的基本流程

推荐操作步骤：

1. 在主页面选择关键数据算法。
2. 如有需要，再选择业务内容分类。
3. 点击“调试”。
4. 使用系统自动生成的基础 JSON 入参模板。
5. 按实际场景补充或修改参数。
6. 点击“调试”查看结果。
7. 如有需要，点击“查看明细”核对执行过程。

#### 6.7.3 自动生成入参

调试弹窗打开后，系统会根据：

- 当前关键数据算法
- 当前业务内容分类
- 当前规则涉及的参数定义

自动生成基础 JSON 模板。

使用价值：

- 减少手工拼装 JSON 的工作量
- 避免漏填关键字段
- 让不同人员调试口径更一致

如果没有完整选择算法或分类，系统仍会生成基础模板，但可能无法进入具体算法分支。

#### 6.7.4 成功案例的保存与复用

调试弹窗支持：

- 选择成功案例
- 反显案例
- 保存成功案例

推荐用法：

1. 对一个典型场景调试成功后，保存为案例。
2. 下次同类场景直接选择案例反显。
3. 在案例基础上微调个别参数后再次调试。

适用场景：

- 购房、租房、还贷等高频业务场景
- 回归测试
- 交接给其他配置人员复用

#### 6.7.5 调试日志明细

调试成功后可查看“调试日志明细”。

日志中一般会体现：

- 当前执行环节
- 日志类型
- 处理内容
- 执行结果
- 执行时间

它适合用于：

- 定位是哪一步标准执行不符合预期
- 查看当前算法分发到了哪个分支
- 辅助比对 SQL 执行结果

### 6.8 业务规则维护建议

- 先同步规则，再配置参数，最后调试。
- 规则参数配置完成后，至少回查一次反显结果。
- 每个关键算法建议保留 2 到 3 个成功调试案例。
- 大批量调整前先做部分导出或全量导出备份。

## 7. 常见使用场景

### 7.1 新增一个业务场景

建议步骤：

1. 在标准库中新增业务内容分类。
2. 在标准库中补充对应模板、属性组、互斥关系。
3. 进入业务规则页面，通过清册选择同步到本机构。
4. 配置节点详细参数。
5. 用典型业务数据调试验证。
6. 保存成功案例。

### 7.2 修改某项标准值

如果修改的是公共模板口径，建议这样处理：

1. 在标准库中修改模板定义或默认标准值。
2. 评估哪些机构规则需要同步。
3. 到业务规则页面检查节点参数是否需要同步调整。
4. 重新调试并保存新案例。

### 7.3 迁移到新环境

建议步骤：

1. 先从标准库页面做全量导出。
2. 在目标环境全量导入标准库。
3. 再从业务规则页面导出对应机构规则。
4. 在目标环境导入业务规则。
5. 抽查参数反显和调试结果。

## 8. 数据库表与存储说明

以下只说明业务上需要关注的表，不展开程序内部实现。

### 8.1 标准库相关表

| 表名 | 用途 | 说明 |
| --- | --- | --- |
| `gjj_ywnrfl` | 业务内容分类表 | 存放算法下的分类编码、分类名称、启用状态 |
| `gjj_ywbzk` | 业务标准库主表 | 存放标准模板主信息 |
| `gjj_ywbzksx` | 标准属性表 | 存放模板需要的参数定义、来源和对象信息 |
| `gjj_ywbzkhc` | 互斥关系表 | 存放模板之间的互斥关系 |

存储特点：

- 标准库数据偏公共模板。
- 通常由模型机构统一维护。
- 导出时会连同分类、属性、互斥关系一起导出。

### 8.2 业务规则相关表

| 表名 | 用途 | 说明 |
| --- | --- | --- |
| `gjj_ywbz` | 业务规则主表 | 存放某机构实际启用的规则 |
| `gjj_ywbzsx` | 规则参数明细表 | 存放“节点详细参数设置”中的具体值 |
| `gjj_ywbz_debug_case` | 调试成功案例表 | 存放调试入参、结果摘要、创建人、创建时间 |
| `gjj_ywblbz_log` | 调试日志表 | 存放调试过程中的执行明细 |

存储特点：

- 业务规则通常按 `jgbh`、`zjgbh` 区分机构范围。
- 同一套标准模板，在不同机构下可以配置不同参数值。
- 调试案例也按机构范围隔离，便于本机构复用。

## 9. 常见问题

### 9.1 为什么标准库页面不能新增或编辑

大多是因为当前登录机构不是模型机构。此时标准库只允许查看、导出和全量导入。

### 9.2 为什么新增了业务内容分类却不能删除

如果该分类已经被标准库模板或业务规则引用，系统通常不允许直接删除。

### 9.3 为什么规则参数抽屉里没有值

常见原因有：

- 该规则还没有保存过参数
- 标准模板没有配置完整属性组
- 本次同步后尚未进行参数维护

### 9.4 为什么调试时建议先选算法和业务内容分类

因为系统需要根据当前算法和分类自动生成入参模板，并匹配正确的算法分支和参数定义。

## 10. 结论

标准库和业务规则的推荐分工如下：

- 标准库解决“模板定义是否完整、是否统一”。
- 业务规则解决“本机构实际用什么、参数值是多少、调试是否通过”。

日常使用中，最重要的不是一次性把所有内容建完，而是形成稳定流程：

1. 分类维护。
2. 模板维护。
3. 规则同步。
4. 参数配置。
5. 调试验证。
6. 导出备份。

按这个顺序使用，标准库和业务规则会更容易维护，也更适合跨环境迁移和长期迭代。
