# 第一部分：部署（必须执行）

本手册用于指导在生产环境通过 `docker-compose.prod.yml` 部署当前项目，重点说明：

- SQLite（系统库）应放置的位置与持久化方式
- `docker-compose.prod.yml` 中需要调整的关键项
- `server/config/datasources.json`（多数据源）应该如何配置与调整

---

## 1. 环境要求与架构说明

### 1.1 服务器要求

| 项目 | 最低配置 | 推荐配置 |
|------|----------|----------|
| **操作系统** | Linux (Ubuntu 20.04+ / CentOS 7+) | Ubuntu 22.04 LTS |
| **Docker** | >= 20.10.x | >= 24.x |
| **Docker Compose** | >= 2.x | >= 2.x |
| **内存** | 2GB | 4GB+ |
| **磁盘** | 10GB 可用空间 | 20GB+ SSD |

### 1.2 架构支持检查

部署前确认 CPU 架构：

```bash
uname -m
```

| 输出结果 | 架构名称 | 说明 |
|----------|----------|------|
| `x86_64` | AMD64 | 常见服务器 |
| `aarch64` | ARM64 | 信创服务器等 |

### 1.3 网络要求

**1）对外服务端口**

`docker-compose.prod.yml` 默认将宿主机端口映射到容器 `80`：

- 默认：宿主机 `30200` → 容器 `80`

如现场端口有要求，请在 `docker-compose.prod.yml` 的 `ports` 中调整。

**2）外部依赖**

本项目运行可能依赖以下外部地址（视现场是否启用/接入）：

- 镜像仓库（在线拉取）：`harbor.sjgjj.cn:10443`（或使用离线镜像导入）
- 业务库：Oracle/达梦（由 `datasources.json` 指定的 `connectString` 决定）
- 统一认证/网关：`GATEWAY_VALIDATE_URL` 指向的地址
- 允许跨域访问的来源：`CORS_ORIGIN` 指定的域名列表

### 1.4 挂载目录与数据持久化（现场重点）

生产部署建议使用一个独立目录（示例：`/opt/damoxing/`），并在该目录下创建 `data/` 与 `config/`：

```text
/opt/damoxing/
  docker-compose.prod.yml
  data/
    database.sqlite         # SQLite 系统库（持久化）
    logs/                   # 应用日志（持久化）
    backups/                # SQLite 备份（持久化）
  config/
    datasources.json        # 业务库多数据源配置（持久化，建议只读挂载）
```

> SQLite（系统库）就是一个文件：`data/database.sqlite`。容器启动时如该文件不存在，会从镜像内置模板自动初始化生成。

## 2. 部署步骤（docker-compose.prod.yml）

### 2.0 离线环境说明（如适用）

如现场服务器无法联网（无法从 Harbor 拉取镜像 / 无法在线安装 Docker），请先按 `docs/1.运维部署手册.md` 中的“离线安装 Docker / Docker Compose / 镜像导入”流程完成环境准备，再继续执行本手册第 2.1 节起的步骤。

### 2.1 准备部署文件

现场交付应至少提供/确认以下文件：

- `docker-compose.prod.yml`
- `config/datasources.json`（按现场数据库配置完成，见 2.4）
- `data/` 目录（首次部署可为空目录；升级/迁移需携带原 `data/`）

#### 2.1.1 交付清单（交付/运维双方签字确认）

建议按以下清单进行交付确认（适用于在线/离线两种现场）：

| 序号 | 项目 | 交付物/位置 | 说明 | 确认 |
|------|------|-------------|------|------|
| 1 | 部署编排文件 | `docker-compose.prod.yml` | 端口、路径前缀、环境变量已按现场要求填好 | ☐ |
| 2 | 多数据源配置 | `config/datasources.json` | Oracle/达梦连接信息与 `jgbh_list` 已按现场配置完成 | ☐ |
| 3 | 数据目录（持久化） | `data/` | 包含 `database.sqlite`/`logs/`/`backups/`，升级场景必须带历史数据 | ☐ |
| 4 | 镜像交付（离线场景） | `*.tar` | 离线环境提供镜像文件与校验值（MD5/SHA256） | ☐ |
| 5 | 版本信息 | 交付说明/邮件 | 镜像 tag、发布日期、变更点、回滚版本说明 | ☐ |
| 6 | 账号与验收数据 | 现场提供 | 用于验收登录/业务查询的账号、至少 1 个可用 `jgbh` | ☐ |
| 7 | 运维资料 | 本文档 + `docs/1.运维部署手册.md` | 离线安装/备份/排障方法对齐 | ☐ |

### 2.2 准备目录（必须）

```bash
cd /opt/damoxing
mkdir -p ./data/logs ./data/backups ./config
```

重要提示（避免挂载踩坑）：

- **必须先创建文件** `./config/datasources.json` 再启动容器；如果该文件不存在，Docker 可能会创建同名目录并挂载，导致后端读取配置时报错（例如 `EISDIR` / JSON 解析失败）。

建议启动前检查：

```bash
test -f ./config/datasources.json && echo "datasources.json OK"
```

### 2.3 配置 docker-compose.prod.yml（需要调整的项）

打开 `docker-compose.prod.yml`，重点确认/调整以下配置项：

1）镜像版本（现场交付常改）

- `services.app.image`：确认 tag 为本次交付版本；离线部署时需与导入镜像一致。

2）端口映射（现场常改）

- `services.app.ports`：例如将 `30200:80` 改成现场要求端口。

3）访问路径（必须按现场网关/反代统一）

- `APP_BASE_PATH`：前端部署子路径，必须以 `/` 开头并以 `/` 结尾（例如 `/gjj_gjsjjsmx/`）
- `API_ROUTE_PREFIX`：API 前缀，必须与前端一致（建议为 `${APP_BASE_PATH}api`，例如 `/gjj_gjsjjsmx/api`）

4）跨域来源（必须按现场域名配置）

- `CORS_ORIGIN`：多个域名用英文逗号分隔（例如 `https://a.example.com,https://b.example.com`）

5）认证与安全（生产必须改）

- `JWT_SECRET`：必须替换为生产强随机值（严禁沿用交付示例）
- `JWT_EXPIRES_IN`：按现场策略调整（例如 `24h`）

6）网关相关（按现场是否接入）

- `GATEWAY_VALIDATE_URL`
- `GATEWAY_ENABLED`
- `SKIP_LOCAL_AUTH`

7）SQLite 与日志目录（通常不改，但需理解）

- `DB_PATH=/app/data/database.sqlite`（对应宿主机 `./data/database.sqlite`）
- `LOG_DIR=/app/data/logs`（对应宿主机 `./data/logs/`）

### 2.4 配置多数据源：config/datasources.json（重点说明）

#### 2.4.1 配置文件在部署中的位置

- 仓库内示例：`server/config/datasources.json`（用于参考结构）
- 生产部署实际使用：`/opt/damoxing/config/datasources.json`
- 容器内读取路径：`/app/config/datasources.json`（由 `docker-compose.prod.yml` 挂载到该路径）

> 容器启动后，可通过以下命令核对挂载是否正确：
```bash
docker compose -f docker-compose.prod.yml exec app sh -lc "ls -la /app/config && cat /app/config/datasources.json"
```

#### 2.4.2 你需要在 datasources.json 中“必须调整”的项

现场部署时，以下字段通常都需要按现场数据库真实信息调整：

1）全局字段

- `default_datasource`：默认数据源 ID（必须等于某个 `datasources[].id`）
- `strict_routing`：生产建议 `true`（避免请求携带未知 `jgbh` 时误落默认库）

2）每个数据源（`datasources[]`）

- `id`：数据源标识（唯一）
- `type`：`oracle` 或 `dm`
- `jgbh_list`：该数据源负责的机构号列表（字符串数组，**不要重复映射**）
- `config.user` / `config.password` / `config.connectString`
- `config.poolMin` / `config.poolMax`：连接池参数（多数据源场景建议保守配置，避免启动时连接数过大）
- 达梦额外字段：`config.loginEncrypt`（布尔值，按现场要求）

#### 2.4.3 datasources.json 结构模板（可直接参考填写）

```json
{
    "default_datasource": "oracle_main",
    "strict_routing": true,
    "datasources": [
        {
            "id": "oracle_main",
            "type": "oracle",
            "jgbh_list": ["1001", "1002"],
            "config": {
                "user": "YOUR_USER",
                "password": "YOUR_PASSWORD",
                "connectString": "10.0.0.10:1521/ORCL",
                "poolMin": 1,
                "poolMax": 10
            }
        },
        {
            "id": "dm_branch_1",
            "type": "dm",
            "jgbh_list": ["2001"],
            "config": {
                "user": "YOUR_USER",
                "password": "YOUR_PASSWORD",
                "connectString": "10.0.0.20:5236",
                "loginEncrypt": false,
                "poolMin": 1,
                "poolMax": 10
            }
        }
    ]
}
```

#### 2.4.4 路由规则说明（运维需要知道的行为）

后端会根据请求中的 `jgbh` 将“业务库查询/写入”路由到不同数据源：

- `jgbh` 的常见来源：
  - 请求 body：`jgbh`
  - 请求头：`jgbh` 或 `zzbs`
- `jgbh` 命中 `datasources[].jgbh_list` 后，使用对应数据源连接池执行 SQL。
- 若请求**未提供** `jgbh`：直接使用 `default_datasource`。
- 若请求提供了 `jgbh` 但未命中映射：
  - `strict_routing=true`：直接报错（推荐生产使用）
  - `strict_routing=false`：回退到 `default_datasource`

安全校验（现场常见问题来源）：

- 若启用了 JWT 鉴权，系统会校验请求头的 `jgbh/zzbs`、`zjgbh/zzjgdmz` 与 Token 中机构信息一致，避免越权路由。

#### 2.4.5 权限与保密建议（生产建议）

`datasources.json` 包含数据库账号密码，建议：

- 文件权限：仅运维可读（示例：`chmod 600 ./config/datasources.json`）
- 严禁将生产账号密码提交到代码仓库

# 第二部分：运维（建议执行）

## 3. 健康检查与巡检建议

常用健康检查端点：

- `GET /health`：快速检查（HTTP 200 即进程可用）
- `GET /health/detailed`：详细检查（包含 SQLite、缓存、内存等信息）

示例：

```bash
curl -fsS http://127.0.0.1:30200/health
curl -fsS http://127.0.0.1:30200/health/detailed
```

> 注意：`/health/detailed` 主要检查系统库（SQLite），不代表业务库（Oracle/达梦）一定全部可用；业务库以启动日志与业务接口实际调用为准。

## 4. 日志查看

### 4.1 容器实时日志

```bash
docker compose -f docker-compose.prod.yml logs -f --tail 200 app
```

### 4.2 宿主机持久化日志

日志默认写入宿主机：

- `./data/logs/combined-YYYY-MM-DD.log`
- `./data/logs/error-YYYY-MM-DD.log`
- `./data/logs/backup.log`（SQLite 备份脚本日志）

## 5. SQLite 备份与恢复（现场必看）

### 5.1 自动备份说明

容器内置定时任务：每天凌晨 **2 点**执行一次在线备份：

- 备份目录：`./data/backups/`
- 保留策略：保留最近 **7 天**备份（自动删除更早备份）
- 备份日志：`./data/logs/backup.log`

### 5.2 手工备份（建议在升级前执行）

```bash
docker compose -f docker-compose.prod.yml exec app sh -lc "/app/backup-db.sh"
ls -la ./data/backups/
```

### 5.3 恢复（回滚场景常用）

1）停止服务：

```bash
docker compose -f docker-compose.prod.yml down
```

2）用备份文件覆盖 SQLite：

```bash
cp ./data/backups/database_YYYYMMDD_HHMMSS.sqlite ./data/database.sqlite
```

3）启动服务：

```bash
docker compose -f docker-compose.prod.yml up -d
```

## 6. 升级与回滚

### 6.1 升级前检查清单

- 手工备份 SQLite（见 5.2）
- 确认 `./config/datasources.json` 未被误改
- 确认磁盘空间充足（`df -h`）

### 6.2 升级步骤

1）更新 `docker-compose.prod.yml` 中 `image` tag（或导入新镜像）
2）拉取/导入后重启：

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

### 6.3 回滚步骤

1）将 `image` tag 改回旧版本（或导入旧镜像）
2）启动：

```bash
docker compose -f docker-compose.prod.yml up -d
```

必要时配合 SQLite 恢复（见 5.3）。

## 8. 常见问题

### Q1：页面白屏或 API 404

重点检查：

- `APP_BASE_PATH` 与 `API_ROUTE_PREFIX` 是否符合现场网关/反代路径
- 访问是否走了正确的子路径（根路径会 301 到 `APP_BASE_PATH`）

### Q2：报错“未找到机构 [jgbh] 对应的数据源配置”（strict_routing）

原因：请求携带了 `jgbh`，但该值未出现在任何 `datasources[].jgbh_list`。

处理：将该 `jgbh` 加入对应数据源的 `jgbh_list`，然后重启容器：

```bash
docker compose -f docker-compose.prod.yml restart app
```

### Q3：业务库连接失败（Oracle/达梦）

排查顺序：

1）检查 `connectString/user/password` 是否正确
2）确认部署机到数据库网络可达（防火墙/路由/端口）
