# 业务标准升级方案

本文档用于整理业务标准相关功能的升级改造方案，覆盖标准库页面、业务规则页面、存储过程拆分以及外围系统对接等内容。

当前版本共整理 9 个改造点，统一按以下结构编写：

- 改造目标
- 逻辑改造
- 页面改造
- 影响范围及兼容性说明

## 改造点总览

| 序号 | 改造点 |
| --- | --- |
| 1 | 关键数据算法下拉改为本地 JSON 配置 |
| 2 | 业务内容分类改为自有维护并通过自有接口取值 |
| 3 | 标准库新增自定义编码字段 |
| 4 | 标准库新增业务办理分类字段并优化新增、修改页面展示 |
| 5 | 业务办理标准支持配置互斥关系 |
| 6 | 关键数据算法按不同子存储过程执行 |
| 7 | 第三方程序对接范围补齐 |
| 8 | 业务办理标准数值在节点详细参数设置中反显具体值 |
| 9 | 调试功能支持业务参数自动生成及成功案例保存反显 |

## 改造点 1：关键数据算法下拉改为本地 JSON 配置

### 1. 改造目标

将当前页面中写死的关键数据算法 1/2/3/4，改为通过本地 UTF-8 JSON 文件统一维护，并在服务启动时读取到内存后使用。

### 2. 逻辑改造

#### 2.1 配置文件

配置文件路径：server/config/business-algorithms.json

建议配置结构：

| 配置项 | 示例值 | 说明 |
| --- | --- | --- |
| value | 1 | 算法编码，对应 gjsjsf / ywsf |
| label | 最大可提取额 | 算法名称 |
| sort | 1 | 排序号 |
| enabled | true | 是否启用 |

建议初始配置保留现有 4 个算法：

| 编码 | 名称 |
| --- | --- |
| 1 | 最大可提取额 |
| 2 | 最高可贷金额 |
| 3 | 最高可贷年限 |
| 4 | 借款人最大可对冲支取金额 |

#### 2.2 后端处理

- 服务启动时统一读取 JSON 文件并缓存到内存。
- 下拉数据、名称映射和算法合法性校验统一使用该内存配置。
- 配置变更采用“修改文件后重启服务生效”的方式。

#### 2.3 存储与校验

- gjj_ywbzk.gjsjsf 和 gjj_ywbz.ywsf 继续保存算法编码。
- 不新增数据库表，不调整现有字段结构。
- 标准库和业务规则相关保存接口增加算法编码合法性校验。

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 标准库页面（server/templates/pages/business_standard.j2） | 查询区算法下拉改为动态取值；新增、编辑弹窗中的算法下拉改为动态取值；列表中的算法名称展示改为动态映射。 |
| 业务规则页面（server/templates/pages/business_rule.j2） | 查询区算法下拉改为动态取值；清册选择弹窗中的算法相关筛选改为动态取值；列表中的算法名称展示改为动态映射。 |

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 配置文件 | server/config/business-algorithms.json |
| 页面模板 | server/templates/pages/business_standard.j2；server/templates/pages/business_rule.j2 |
| 后端逻辑 | 算法配置读取、缓存、名称映射、接口校验 |
| 兼容性说明 | 不改数据库表结构；不改现有算法编码字段；不影响现有 1/2/3/4 数据；后续新增算法时只需增加 JSON 配置并同步补充对应逻辑。 |

### 5. 已上线数据库投产 SQL

本改造点仅涉及本地 JSON 配置和服务启动时的内存缓存，不涉及数据库新增表或新增字段。

- Oracle：无需执行数据库 DDL。
- 达梦：无需执行数据库 DDL。
- 人大金仓：无需执行数据库 DDL。

## 改造点 2：业务内容分类改为自有维护并通过自有接口取值

### 1. 改造目标

将当前依赖平台接口返回的业务内容分类，改为由系统自有表维护并通过自有接口提供，同时支持在标准库页面中新增、修改、删除业务内容分类。

业务内容分类与关键数据算法存在关联关系，因此分类基础数据需按关键数据算法维度维护。

### 2. 逻辑改造

#### 2.1 业务内容分类基础表

新增表：gjj_ywnrfl

建议字段：

| 字段名 | 说明 |
| --- | --- |
| id | 主键 |
| gjsjsf | 所属关键算法编码 |
| flbm | 业务内容分类编码 |
| flmc | 业务内容分类名称 |
| pxh | 排序号 |
| sfqy | 是否启用 |
| cjsj | 创建时间 |
| gxsj | 更新时间 |

#### 2.2 下拉接口

- 原 tools/business-content-classes 接口由调用平台接口改为查询 gjj_ywnrfl 表。
- 查询时按当前 gjsjsf 过滤，仅返回启用数据，按 pxh、id 排序。
- 返回结构保持不变：value 对应 flbm，label 对应 flmc。

#### 2.3 存储方式

- gjj_ywbzk.ywnrfl 和 gjj_ywbz.ywnrfl 继续保存分类编码。
- 本次仅调整分类数据来源，不调整现有字段结构。

#### 2.4 分类维护能力

需新增 gjj_ywnrfl 的基础 CRUD 接口，支持新增、修改、删除。

维护约束：

| 约束项 | 说明 |
| --- | --- |
| 关键算法必填 | 新增和修改时必须选择所属关键算法 gjsjsf |
| 编码唯一性 | flbm 建议在同一关键算法下唯一 |
| 删除校验 | 删除前需校验是否已被标准库或业务规则引用 |

#### 2.5 基础数据初始化

上线前需初始化现有业务内容分类数据，可通过初始化 SQL、后台脚本或数据库手工维护完成。

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 标准库页面（server/templates/pages/business_standard.j2） | 业务内容分类下拉改为调用自有接口；下拉按当前关键算法联动过滤；新增工具栏按钮“业务内容分类维护”；维护弹窗支持新增、修改、删除；新增、修改表单中增加“关键数据算法”下拉。 |
| 业务规则页面（server/templates/pages/business_rule.j2） | 查询区业务内容分类下拉改为调用自有接口；下拉按当前关键算法联动过滤；清册选择弹窗中的业务内容分类筛选改为调用自有接口；列表中的业务内容分类名称改为基于自有数据源展示。 |

页面边界：本次不新增独立的业务内容分类管理页面，统一通过标准库页面按钮弹窗维护。

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 数据库结构 | 新增 gjj_ywnrfl 表及 gjsjsf 字段 |
| 页面模板 | server/templates/pages/business_standard.j2；server/templates/pages/business_rule.j2 |
| 后端逻辑 | server/routes/http/tools.js 及业务内容分类 CRUD、查询、联动过滤逻辑 |
| 兼容性说明 | 不调整 gjj_ywbzk.ywnrfl、gjj_ywbz.ywnrfl 字段结构；不改变现有分类编码存储方式；历史数据可继续使用；上线前需完成 gjj_ywnrfl 基础数据初始化。 |

### 5. 已上线数据库投产 SQL

本改造点的投产 SQL 已拆分到独立脚本，请按数据库类型执行对应文件中的“改造点 2”段落：

## 改造点 3：标准库新增自定义编码字段

### 1. 改造目标

在标准库中新增稳定、可维护的业务标准编码字段，为后续程序和存储过程按编码识别业务办理标准提供统一基础。

### 2. 逻辑改造

#### 2.1 新增字段

在 gjj_ywbzk 表中新增字段：zdybm

字段要求：

| 要求项 | 说明 |
| --- | --- |
| 可维护 | 支持手工录入和修改 |
| 唯一性 | 同一标准库内保持唯一 |
| 取值规范 | 建议使用英文、数字、下划线等稳定字符 |

#### 2.2 标准库读写逻辑

标准库相关接口和导入导出逻辑需同步支持 zdybm：

- 列表查询
- 详情查询
- 新增保存
- 编辑保存
- 导入导出

#### 2.3 后续使用方式

后续程序或存储过程识别业务标准时，应优先基于 zdybm 判断，不再优先依赖 ywblbz、id 或页面展示名称。

#### 2.4 历史数据处理

字段新增后，需为已有标准库数据逐步补齐编码；若后续逻辑依赖 zdybm，则对应标准必须先完成补码。

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 标准库页面（server/templates/pages/business_standard.j2） | 查询区增加自定义编码筛选；新增、编辑弹窗增加“自定义编码”录入项；列表增加“自定义编码”展示列。 |
| 业务规则页面 | 本次原则上不新增维护入口；如有需要，可在后续版本增加只读展示。 |

页面边界：本次只解决标准库自定义编码可维护的问题，不扩展为独立编码管理体系。

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 数据库结构 | gjj_ywbzk 表新增 zdybm 字段 |
| 页面模板 | server/templates/pages/business_standard.j2 |
| 后端逻辑 | server/routes/http/ywbzk.js、导入导出逻辑、后续按编码识别标准的程序逻辑 |

## 改造点 4：标准库新增业务办理分类字段并优化新增、修改页面展示

### 1. 改造目标

在标准库中新增“业务办理分类”字段，用于区分标准类模板和条件类模板，并根据不同分类动态调整新增、修改页面的表单展示。

### 2. 逻辑改造

#### 2.1 新增字段

在 gjj_ywbzk 表中新增字段：ywblfl

建议取值：

| 编码 | 名称 |
| --- | --- |
| 1 | 标准 |
| 2 | 条件 |

#### 2.2 标准库读写逻辑

标准库相关接口和导入导出逻辑需同步支持 ywblfl。

#### 2.3 条件类模板执行语句

- 选择“标准”时保留当前录入方式。

页面展示建议：

## 改造点 5：业务办理标准支持配置互斥关系

### 1. 改造目标

支持在标准库中配置业务办理标准之间的互斥关系，并在业务规则页面勾选标准时限制同一业务内容分类下的互斥标准不能同时选中。

### 2. 逻辑改造

#### 2.1 新增互斥关系表

建议新增表：gjj_ywbzkhc

建议字段：

| 字段名 | 说明 |
| --- | --- |
| id | 主键 |

#### 2.2 配置范围约束

互斥关系建议限制在：

- 同一关键数据算法
- 同一业务内容分类
- 非自身模板

#### 2.3 标准库读写逻辑

#### 2.4 勾选校验

#### 2.5 后端兜底校验

业务规则批量保存接口需增加互斥关系兜底校验，防止绕过前端直接写入冲突数据。

### 3. 页面改造

## 改造点 6：关键数据算法按不同子存储过程执行

### 1. 改造目标

将当前集中在同一个主存储过程中的关键算法执行逻辑，调整为“统一入口分发 + 不同关键算法调用不同子存储过程”的方式，降低耦合并提升扩展性。

### 2. 逻辑改造

#### 2.1 保留统一入口

统一入口过程继续作为外部调用入口，负责接收入参、按关键算法编码分发到对应子存储过程，并汇总最终结果。

#### 2.2 拆分子存储过程

建议按算法拆分为独立子存储过程：

- 最大可提取额
- 最高可贷金额
- 最高可贷年限
- 借款人最大可对冲支取金额

后续新增算法时，继续按相同模式增加子存储过程。

#### 2.3 通用能力下沉

以下能力建议继续保留为公共函数或公共逻辑：

- 方言 SQL 解析
- 标准值解析
- 页面参数读取
- 动态 SQL 预处理
- 执行日志写入

#### 2.4 调用关系

- 外部程序继续调用统一入口。
- 统一入口按算法编码分发。
- 子存储过程只处理本算法相关逻辑。

#### 2.5 历史逻辑迁移

建议按算法逐步迁移：

- 先抽离一个算法作为样板
- 验证入口分发和日志输出
- 再逐步迁移其他算法

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |

## 改造点 8：业务办理标准数值在节点详细参数设置中反显具体值

### 1. 改造目标

在业务办理标准配置场景中，节点详细参数设置页面不仅展示参数项名称，还需要准确反显当前业务办理标准对应的具体数值，方便业务人员直接核对、理解和调整配置。

### 2. 逻辑改造

#### 2.1 参数明细查询补齐

节点详细参数设置接口需返回业务办理标准相关的参数明细值，至少包括：

- 参数名称
- 参数编码
- 参数当前值
- 参数值展示文本
- 值类型或取值方式

#### 2.2 反显规则

- 当业务标准存在已配置数值时，页面打开节点详细参数设置抽屉后直接回显该值。
- 当数值来源于字典、下拉或映射关系时，页面需优先展示可读名称，必要时同时保留原始值。
- 当业务标准尚未配置具体值时，页面保留空值状态，避免误展示默认值。

#### 2.3 保存一致性

节点详细参数设置保存后，重新打开页面时应能继续看到最新保存值，确保“查询、展示、保存、再次展示”链路一致。

#### 2.4 前端改造点

- 业务规则页面打开“规则参数配置”抽屉时，动态表单需带出当前规则 ID、模板 ID 及参数值明细。
- 动态表单中涉及文本框、数字框、下拉框、单选框等组件时，均需支持基于返回值直接反显。
- 对于下拉和映射型字段，前端除保存原始值外，还需展示对应名称，避免页面仅显示编码。
- 保存成功后需刷新当前抽屉或重新拉取详情，确保页面展示与数据库保存结果一致。

#### 2.5 后端改造点

- `server/routes/http/ywbz/config_form` 返回动态表单 schema 时，需同步注入各参数当前值。
- 如当前接口仅返回表单结构，需补充详情查询逻辑，将参数定义与已保存值合并后再返回前端。
- 保存接口需保证参数值写入后可被详情接口直接读回，避免出现“保存成功但重新打开不回显”的问题。
- 对于枚举、字典、远程下拉类型参数，后端应尽量同时返回原始值和值名称，降低前端二次转换复杂度。

#### 2.6 数据影响说明

- 本次原则上优先复用现有参数配置存储结构，不新增无必要的数据表。
- 若当前参数值仅存在运行态未落库，需补齐持久化存储，至少保证规则维度下的参数值可查询。
- 历史已配置数据需支持迁移或兼容读取，避免新页面上线后旧数据无法回显。

## 改造点 9：调试功能支持业务参数自动生成及成功案例保存反显

### 1. 改造目标

在关键数据计算模型的调试功能中，调试 JSON 入参不再完全依赖人工手写，而是根据当前关键数据算法、业务内容分类及业务参数定义自动生成基础入参模板。配置人员只需按调试需要修改参数值即可发起验证。同时支持将调试成功的请求参数保存为案例，供其他人员直接选择、反显并复用。

### 2. 逻辑改造

#### 2.1 调试入参自动生成

- 打开调试弹窗时，系统根据当前算法、业务内容分类和调试参数定义自动生成 JSON 模板。
- 模板中默认带出必要业务参数，例如关键算法编码、业务内容分类、机构编号及该算法对应的常用业务字段。
- 对于可推导的字段优先自动填充默认值或示例值，减少人工拼装成本。

#### 2.2 成功案例保存

- 当一次调试执行成功后，支持将本次请求参数保存为“调试成功案例”。
- 保存内容建议至少包括：算法编码、业务内容分类、案例名称、请求参数 JSON、调试结果摘要、创建人、创建时间。
- 同一算法下可保存多条案例，便于覆盖不同业务场景。

#### 2.3 案例反显与复用

- 调试弹窗中增加“选择案例”或“历史成功案例”入口。
- 选中某个成功案例后，自动将其请求参数反显到 JSON 编辑器中，配置人员可直接再次调试，或在此基础上修改少量字段后验证。
- 反显时保留案例原始结构，避免字段缺失或顺序混乱影响理解。

#### 2.4 前端改造点

- `server/templates/pages/business_rule.j2` 中调试弹窗需增加“自动生成入参”“保存案例”“选择案例/反显案例”相关交互。
- JSON 编辑器初始化时优先加载自动生成模板；选择案例后覆盖当前编辑区内容。
- 调试成功后按钮区支持一键保存当前请求参数为案例。
- 案例列表建议展示案例名称、算法、业务内容分类、创建人、创建时间，并支持点击后反显。

#### 2.5 后端改造点

- 新增调试入参模板生成接口，按算法和业务内容分类返回推荐 JSON 结构。
- 新增调试案例保存、查询、详情接口，支持按算法、业务内容分类过滤。
- 保存案例时建议校验 JSON 合法性，并限制仅保存调试成功的数据，避免无效样例沉淀。
- 详情接口返回时需保持 JSON 原始结构，确保前端反显一致。

#### 2.6 数据影响说明

- 建议新增调试案例表，按算法、业务内容分类和案例维度存储请求参数样例。
- 如暂不建表，也可先采用 JSON 文件或其他配置存储，但长期建议落库以支持检索、权限和审计。
- 历史未保存案例的数据不受影响，原有手工调试方式仍可保留作为兜底。
