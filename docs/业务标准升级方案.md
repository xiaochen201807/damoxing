# 业务标准升级方案

本文档用于整理业务标准相关功能的升级改造方案，覆盖标准库页面、业务规则页面、存储过程拆分以及外围系统对接等内容。

当前版本共整理 7 个改造点，统一按以下结构编写：

- 改造目标
- 逻辑改造
- 页面改造
- 影响范围及兼容性说明

## 改造点总览

| 序号 | 改造点 |
| --- | --- |
| 1 | 关键数据算法下拉改为本地 JSON 配置 |
| 2 | 业务内容分类改为自有维护并通过自有接口取值 |
| 3 | 标准库新增自定义编码字段 |
| 4 | 标准库新增业务办理分类字段并优化新增、修改页面展示 |
| 5 | 业务办理标准支持配置互斥关系 |
| 6 | 关键数据算法按不同子存储过程执行 |
| 7 | 第三方程序对接范围补齐 |

## 改造点 1：关键数据算法下拉改为本地 JSON 配置

### 1. 改造目标

将当前页面中写死的关键数据算法 1/2/3/4，改为通过本地 UTF-8 JSON 文件统一维护，并在服务启动时读取到内存后使用。

### 2. 逻辑改造

#### 2.1 配置文件

配置文件路径：server/config/business-algorithms.json

建议配置结构：

| 配置项 | 示例值 | 说明 |
| --- | --- | --- |
| value | 1 | 算法编码，对应 gjsjsf / ywsf |
| label | 最大可提取额 | 算法名称 |
| sort | 1 | 排序号 |
| enabled | true | 是否启用 |

建议初始配置保留现有 4 个算法：

| 编码 | 名称 |
| --- | --- |
| 1 | 最大可提取额 |
| 2 | 最高可贷金额 |
| 3 | 最高可贷年限 |
| 4 | 借款人最大可对冲支取金额 |

#### 2.2 后端处理

- 服务启动时统一读取 JSON 文件并缓存到内存。
- 下拉数据、名称映射和算法合法性校验统一使用该内存配置。
- 配置变更采用“修改文件后重启服务生效”的方式。

#### 2.3 存储与校验

- gjj_ywbzk.gjsjsf 和 gjj_ywbz.ywsf 继续保存算法编码。
- 不新增数据库表，不调整现有字段结构。
- 标准库和业务规则相关保存接口增加算法编码合法性校验。

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 标准库页面（server/templates/pages/business_standard.j2） | 查询区算法下拉改为动态取值；新增、编辑弹窗中的算法下拉改为动态取值；列表中的算法名称展示改为动态映射。 |
| 业务规则页面（server/templates/pages/business_rule.j2） | 查询区算法下拉改为动态取值；清册选择弹窗中的算法相关筛选改为动态取值；列表中的算法名称展示改为动态映射。 |

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 配置文件 | server/config/business-algorithms.json |
| 页面模板 | server/templates/pages/business_standard.j2；server/templates/pages/business_rule.j2 |
| 后端逻辑 | 算法配置读取、缓存、名称映射、接口校验 |
| 兼容性说明 | 不改数据库表结构；不改现有算法编码字段；不影响现有 1/2/3/4 数据；后续新增算法时只需增加 JSON 配置并同步补充对应逻辑。 |

## 改造点 2：业务内容分类改为自有维护并通过自有接口取值

### 1. 改造目标

将当前依赖平台接口返回的业务内容分类，改为由系统自有表维护并通过自有接口提供，同时支持在标准库页面中新增、修改、删除业务内容分类。

业务内容分类与关键数据算法存在关联关系，因此分类基础数据需按关键数据算法维度维护。

### 2. 逻辑改造

#### 2.1 业务内容分类基础表

新增表：gjj_ywnrfl

建议字段：

| 字段名 | 说明 |
| --- | --- |
| id | 主键 |
| gjsjsf | 所属关键算法编码 |
| flbm | 业务内容分类编码 |
| flmc | 业务内容分类名称 |
| pxh | 排序号 |
| sfqy | 是否启用 |
| cjsj | 创建时间 |
| gxsj | 更新时间 |

#### 2.2 下拉接口

- 原 tools/business-content-classes 接口由调用平台接口改为查询 gjj_ywnrfl 表。
- 查询时按当前 gjsjsf 过滤，仅返回启用数据，按 pxh、id 排序。
- 返回结构保持不变：value 对应 flbm，label 对应 flmc。

#### 2.3 存储方式

- gjj_ywbzk.ywnrfl 和 gjj_ywbz.ywnrfl 继续保存分类编码。
- 本次仅调整分类数据来源，不调整现有字段结构。

#### 2.4 分类维护能力

需新增 gjj_ywnrfl 的基础 CRUD 接口，支持新增、修改、删除。

维护约束：

| 约束项 | 说明 |
| --- | --- |
| 关键算法必填 | 新增和修改时必须选择所属关键算法 gjsjsf |
| 编码唯一性 | flbm 建议在同一关键算法下唯一 |
| 删除校验 | 删除前需校验是否已被标准库或业务规则引用 |

#### 2.5 基础数据初始化

上线前需初始化现有业务内容分类数据，可通过初始化 SQL、后台脚本或数据库手工维护完成。

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 标准库页面（server/templates/pages/business_standard.j2） | 业务内容分类下拉改为调用自有接口；下拉按当前关键算法联动过滤；新增工具栏按钮“业务内容分类维护”；维护弹窗支持新增、修改、删除；新增、修改表单中增加“关键数据算法”下拉。 |
| 业务规则页面（server/templates/pages/business_rule.j2） | 查询区业务内容分类下拉改为调用自有接口；下拉按当前关键算法联动过滤；清册选择弹窗中的业务内容分类筛选改为调用自有接口；列表中的业务内容分类名称改为基于自有数据源展示。 |

页面边界：本次不新增独立的业务内容分类管理页面，统一通过标准库页面按钮弹窗维护。

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 数据库结构 | 新增 gjj_ywnrfl 表及 gjsjsf 字段 |
| 页面模板 | server/templates/pages/business_standard.j2；server/templates/pages/business_rule.j2 |
| 后端逻辑 | server/routes/http/tools.js 及业务内容分类 CRUD、查询、联动过滤逻辑 |
| 兼容性说明 | 不调整 gjj_ywbzk.ywnrfl、gjj_ywbz.ywnrfl 字段结构；不改变现有分类编码存储方式；历史数据可继续使用；上线前需完成 gjj_ywnrfl 基础数据初始化。 |

## 改造点 3：标准库新增自定义编码字段

### 1. 改造目标

在标准库中新增稳定、可维护的业务标准编码字段，为后续程序和存储过程按编码识别业务办理标准提供统一基础。

### 2. 逻辑改造

#### 2.1 新增字段

在 gjj_ywbzk 表中新增字段：zdybm

字段要求：

| 要求项 | 说明 |
| --- | --- |
| 可维护 | 支持手工录入和修改 |
| 唯一性 | 同一标准库内保持唯一 |
| 取值规范 | 建议使用英文、数字、下划线等稳定字符 |

#### 2.2 标准库读写逻辑

标准库相关接口和导入导出逻辑需同步支持 zdybm：

- 列表查询
- 详情查询
- 新增保存
- 编辑保存
- 导入导出

#### 2.3 后续使用方式

后续程序或存储过程识别业务标准时，应优先基于 zdybm 判断，不再优先依赖 ywblbz、id 或页面展示名称。

#### 2.4 历史数据处理

字段新增后，需为已有标准库数据逐步补齐编码；若后续逻辑依赖 zdybm，则对应标准必须先完成补码。

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 标准库页面（server/templates/pages/business_standard.j2） | 查询区增加自定义编码筛选；新增、编辑弹窗增加“自定义编码”录入项；列表增加“自定义编码”展示列。 |
| 业务规则页面 | 本次原则上不新增维护入口；如有需要，可在后续版本增加只读展示。 |

页面边界：本次只解决标准库自定义编码可维护的问题，不扩展为独立编码管理体系。

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 数据库结构 | gjj_ywbzk 表新增 zdybm 字段 |
| 页面模板 | server/templates/pages/business_standard.j2 |
| 后端逻辑 | server/routes/http/ywbzk.js、导入导出逻辑、后续按编码识别标准的程序逻辑 |
| 兼容性说明 | 不改变现有 gjj_ywbzk.id 的主键含义；历史数据未补充 zdybm 时仍可查询和展示；依赖 zdybm 的后续逻辑上线前需先补齐相关标准编码。 |

## 改造点 4：标准库新增业务办理分类字段并优化新增、修改页面展示

### 1. 改造目标

在标准库中新增“业务办理分类”字段，用于区分标准类模板和条件类模板，并根据不同分类动态调整新增、修改页面的表单展示。

### 2. 逻辑改造

#### 2.1 新增字段

在 gjj_ywbzk 表中新增字段：ywblfl

建议取值：

| 编码 | 名称 |
| --- | --- |
| 1 | 标准 |
| 2 | 条件 |

#### 2.2 标准库读写逻辑

标准库相关接口和导入导出逻辑需同步支持 ywblfl。

#### 2.3 条件类模板执行语句

当 ywblfl=1 时，页面和数据保存方式保持现状。  
当 ywblfl=2 时，页面下方内容切换为“业务条件执行语句”，仍保存到 gjj_ywbzk.ywbzjg。

#### 2.4 展示约束

- 选择“标准”时保留当前录入方式。
- 选择“条件”时切换为条件类录入方式。
- 条件类模板保存时，执行语句仍写入 ywbzjg。

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 标准库新增页面（server/templates/pages/business_standard.j2） | 在“业务内容分类”下方新增“业务办理分类”下拉；选择“标准”时保留当前表单；选择“条件”时切换为“业务条件执行语句”录入模式。 |
| 标准库修改页面（server/templates/pages/business_standard.j2） | 编辑弹窗同步增加“业务办理分类”下拉；正确回显历史分类值；根据分类值动态调整页面下方展示内容。 |

页面展示建议：

- 业务办理分类放置在“业务内容分类”和“业务办理标准分类”之间。
- 标准类保留现有标准值、结果执行语句等内容。
- 条件类展示“业务条件执行语句”，并减少无关干扰项。

页面边界：本次仅调整标准库新增、修改页面，不扩展到业务规则页面。

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 数据库结构 | gjj_ywbzk 表新增 ywblfl |
| 页面模板 | server/templates/pages/business_standard.j2 |
| 后端逻辑 | server/routes/http/ywbzk.js 及标准库导入导出逻辑 |
| 兼容性说明 | 不新增新的执行语句字段，继续复用 ywbzjg；历史数据如未设置 ywblfl，需补默认值；选择“标准”时现有录入和保存方式保持不变。 |

## 改造点 5：业务办理标准支持配置互斥关系

### 1. 改造目标

支持在标准库中配置业务办理标准之间的互斥关系，并在业务规则页面勾选标准时限制同一业务内容分类下的互斥标准不能同时选中。

### 2. 逻辑改造

#### 2.1 新增互斥关系表

建议新增表：gjj_ywbzkhc

建议字段：

| 字段名 | 说明 |
| --- | --- |
| id | 主键 |
| mbid | 当前标准库模板 ID |
| hcmbid | 互斥标准库模板 ID |
| cjsj | 创建时间 |
| gxsj | 更新时间 |

#### 2.2 配置范围约束

互斥关系建议限制在：

- 同一关键数据算法
- 同一业务内容分类
- 非自身模板

#### 2.3 标准库读写逻辑

标准库详情、保存、删除、导入导出需同步支持互斥关系数据。

#### 2.4 勾选校验

业务规则页面勾选标准时，若与已选标准存在互斥关系，则不允许同时选中，并给出明确提示。

#### 2.5 后端兜底校验

业务规则批量保存接口需增加互斥关系兜底校验，防止绕过前端直接写入冲突数据。

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 标准库页面（server/templates/pages/business_standard.j2） | 新增、编辑页面增加“互斥业务办理标准”配置项；互斥可选项过滤为同一关键算法、同一业务内容分类下的其他标准。 |
| 业务规则页面（server/templates/pages/business_rule.j2） | 清册选择弹窗勾选时增加互斥限制；已选择某标准后，其互斥标准禁止再次勾选或自动取消勾选；页面给出明确提示。 |

页面边界：本次只支持互斥关系，不扩展为依赖、包含、优先级覆盖等更复杂的规则组合。

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 数据库结构 | 新增 gjj_ywbzkhc 表 |
| 页面模板 | server/templates/pages/business_standard.j2；server/templates/pages/business_rule.j2 |
| 后端逻辑 | server/routes/http/ywbzk.js、server/routes/http/ywbz.js 及互斥校验逻辑 |
| 兼容性说明 | 未配置互斥关系时仍按原逻辑使用；新增互斥关系后，仅限制冲突标准不能同时勾选；历史冲突数据需在上线前清理或在页面加载时提示。 |

## 改造点 6：关键数据算法按不同子存储过程执行

### 1. 改造目标

将当前集中在同一个主存储过程中的关键算法执行逻辑，调整为“统一入口分发 + 不同关键算法调用不同子存储过程”的方式，降低耦合并提升扩展性。

### 2. 逻辑改造

#### 2.1 保留统一入口

统一入口过程继续作为外部调用入口，负责接收入参、按关键算法编码分发到对应子存储过程，并汇总最终结果。

#### 2.2 拆分子存储过程

建议按算法拆分为独立子存储过程：

- 最大可提取额
- 最高可贷金额
- 最高可贷年限
- 借款人最大可对冲支取金额

后续新增算法时，继续按相同模式增加子存储过程。

#### 2.3 通用能力下沉

以下能力建议继续保留为公共函数或公共逻辑：

- 方言 SQL 解析
- 标准值解析
- 页面参数读取
- 动态 SQL 预处理
- 执行日志写入

#### 2.4 调用关系

- 外部程序继续调用统一入口。
- 统一入口按算法编码分发。
- 子存储过程只处理本算法相关逻辑。

#### 2.5 历史逻辑迁移

建议按算法逐步迁移：

- 先抽离一个算法作为样板
- 验证入口分发和日志输出
- 再逐步迁移其他算法

### 3. 页面改造

| 页面 | 调整内容 |
| --- | --- |
| 业务规则页面（server/templates/pages/business_rule.j2） | 调试功能继续保留统一入口调用方式；调试结果和日志应能体现实际调用的子存储过程或算法分支。 |
| 算法说明区域 | 页面中的关键算法说明应与拆分后的子存储过程执行方式保持一致。 |

页面边界：本次页面仅做调试和说明层面的配套调整，不改变标准库页面和业务规则页面主流程。

### 4. 影响范围及兼容性说明

| 类别 | 内容 |
| --- | --- |
| 存储过程与函数 | 统一入口、各算法子存储过程、公共函数 |
| 页面模板 | server/templates/pages/business_rule.j2 |
| 后端逻辑 | 调试接口、调试日志展示、直接调用存储过程的后端服务 |
| 兼容性说明 | 建议保留统一入口过程，降低外部接口变更范围；历史调用方可继续通过统一入口执行；拆分后各算法结果口径应与现有逻辑保持一致。 |

## 改造点 7：第三方程序对接范围补齐

### 1. 改造目标

补齐第三方程序侧对关键算法的接入范围。

当前现状：

| 场景 | 现状 |
| --- | --- |
| 业务运行配置 | 已通过 API 接口实现对关键算法的引用 |
| 事项定义工具 | 尚未对接 |
| 定时任务 | 尚未对接 |

### 2. 逻辑改造

#### 2.1 业务运行配置

保持现有调用方式不变，并作为事项定义工具和定时任务对接的参考模式。

#### 2.2 事项定义工具

需补齐以下能力：

- 引用关键算法
- 传入事项场景参数
- 获取关键算法执行结果

#### 2.3 定时任务

需补齐以下能力：

- 引用关键算法
- 按预设参数或业务上下文触发执行
- 记录执行结果和异常信息

#### 2.4 统一调用方式

建议第三方程序统一通过同一套关键算法调用入口接入，统一调用入口、入参格式、返回结构以及异常和日志处理方式。

#### 2.5 对接验证

建议至少验证以下内容：

- 业务运行配置调用结果是否保持一致
- 事项定义工具是否能正确引用并执行关键算法
- 定时任务是否能正确触发关键算法执行
- 异常场景下是否能记录日志并返回清晰错误信息

### 3. 页面改造

| 页面或工具 | 调整内容 |
| --- | --- |
| 业务运行配置页面 | 原则上保持现有页面调用方式不变；如调用入口调整，同步调整调用说明或参数配置方式。 |
| 事项定义工具页面 | 补齐关键算法引用能力，支持选择或配置关键算法，并传递事项上下文参数。 |
| 定时任务配置页面 | 补齐关键算法引用能力，支持配置关键算法调用并查看执行结果或异常状态。 |

页面边界：本次重点是补齐外围系统调用入口，不改变标准库和业务规则页面主流程，也不新增新的关键算法配置模型。
