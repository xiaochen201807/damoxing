## 数据库连接

### 方法一:本地开发环境连接 (本地数据库文件)

适用于在本地开发机器上运行项目的情况。

#### 使用 DBeaver 连接本地数据库

1. **打开 DBeaver**,点击 "新建连接" (或点击工具栏的插头图标)
2. **选择数据库类型**: SQLite
3. **配置连接**:
   - **Path**: `/Users/xiaochen/Downloads/damoxing/server/database.sqlite`
   - **Database**: 留空
4. **测试连接**,然后点击 "完成"

---

### 方法二:远程服务器连接 (推荐) ⭐

适用于数据库文件在远程服务器上的情况。有两种连接方式:

#### 方式 A: 使用 SSH 隧道 + SFTP (推荐)

这是最常用的方式,通过 SSH 连接服务器,然后访问数据库文件。

**步骤 1: 创建 SSH 隧道连接**

1. **打开 DBeaver**,点击 "新建连接"
2. **选择数据库类型**: SQLite
3. **配置 SSH 隧道**:
   - 点击 "SSH" 标签页
   - 勾选 "使用 SSH 隧道"
   - 配置 SSH 连接:
     - **Host/IP**: 你的服务器 IP 地址 (例如: `192.168.1.100` 或 `your-server.com`)
     - **Port**: SSH 端口 (默认 22)
     - **User Name**: SSH 用户名 (例如: `root` 或 `ubuntu`)
     - **Authentication Method**: 
       - 选择 "Public Key" (推荐) 或 "Password"
       - 如果选择 Public Key,指定私钥文件路径 (例如: `~/.ssh/id_rsa`)
       - 如果选择 Password,输入 SSH 密码
   - 点击 "Test tunnel configuration" 测试 SSH 连接

**步骤 2: 配置数据库路径**

4. **切换到 "Main" 标签页**
5. **配置数据库路径**:
   - **Path**: 服务器上数据库文件的**绝对路径**
     - 开发环境: `/path/to/damoxing/server/database.sqlite`
     - Docker 生产环境: `/path/to/damoxing/data/database.sqlite`
   - **Database**: 留空

6. **测试连接**,然后点击 "完成"

**示例配置**:

```
SSH 配置:
  Host: 192.168.1.100
  Port: 22
  User: ubuntu
  Auth: Public Key (/Users/xiaochen/.ssh/id_rsa)

数据库配置:
  Path: /home/ubuntu/damoxing/server/database.sqlite
```

---

#### 方式 B: 先下载数据库文件到本地 (适合临时查看)

如果只是临时查看数据,可以先下载数据库文件到本地。

**步骤 1: 从服务器下载数据库**

```bash
# 使用 scp 下载数据库文件
scp user@server-ip:/path/to/damoxing/server/database.sqlite ~/Downloads/database-remote.sqlite

# 例如:
scp ubuntu@192.168.1.100:/home/ubuntu/damoxing/server/database.sqlite ~/Downloads/database-remote.sqlite
```

**步骤 2: 连接本地下载的文件**

1. **打开 DBeaver**,点击 "新建连接"
2. **选择数据库类型**: SQLite
3. **配置连接**:
   - **Path**: `~/Downloads/database-remote.sqlite`
   - **Database**: 留空
4. **测试连接**,然后点击 "完成"

**⚠️ 注意**: 
- 这种方式修改的是本地副本,不会影响服务器上的数据库
- 如果需要同步修改,需要手动上传回服务器:
  ```bash
  scp ~/Downloads/database-remote.sqlite user@server-ip:/path/to/damoxing/server/database.sqlite
  ```

如果数据库在 Docker 容器中,需要先找到数据库文件的实际位置。

#### 查找数据库文件位置

```bash
# 方法 1: 查看 Volume 映射

# 方法 2: 查看宿主机映射路径
# 数据库文件实际在宿主机的 ./data/database.sqlite

```

#### 连接方式

**如果在服务器上**:
- 使用 "方式 A: SSH 隧道",路径设为: `/path/to/damoxing/data/database.sqlite`

**如果在本地 Docker**:
- 使用 "方法一: 本地连接",路径设为: `/path/to/damoxing/data/database.sqlite`

### 常见问题

#### Q1: SSH 连接失败怎么办?

**检查清单**:
1. 确认服务器 IP 和端口是否正确
2. 确认 SSH 用户名和密码/密钥是否正确
3. 确认服务器防火墙是否开放 SSH 端口 (22)
4. 尝试在终端测试 SSH 连接:
   ```bash
   ssh user@server-ip
   ```

#### Q2: 数据库文件路径找不到?

**解决方案**:
```bash
# 登录服务器
ssh user@server-ip

# 查找数据库文件
find /home -name "database.sqlite" 2>/dev/null

# 或者进入项目目录查看
cd /path/to/damoxing
ls -la server/database.sqlite
ls -la data/database.sqlite
```

#### Q3: 连接成功但看不到表?

**可能原因**:
1. 数据库文件是空的,需要运行迁移:
   ```bash
   cd /path/to/damoxing/server
   npm run db:migrate
   ```
2. 路径指向了错误的数据库文件

#### Q4: 修改数据后前端没有更新?

**原因**: 菜单数据有缓存

**解决方案**:
```bash
# 在服务器上重启后端服务
cd /path/to/damoxing/server
# 如果使用 PM2
pm2 restart damoxing-api

# 如果使用 Docker
docker-compose restart

# 或者等待缓存自动过期 (5分钟)
```

#### Q5: 多人同时连接会有问题吗?

**SQLite 并发限制**:
- SQLite 支持多个读连接,但只支持一个写连接
- 如果多人同时修改数据,可能会出现 "database is locked" 错误
- **建议**: 团队协调,避免同时修改数据

#### Q6: 如何设置只读连接?

在 DBeaver 中:
1. 右键点击连接 → "编辑连接"
2. 切换到 "Connection settings" 标签
3. 在 "URL" 中添加参数: `?mode=ro`
4. 例如: `jdbc:sqlite:/path/to/database.sqlite?mode=ro`

### 安全建议

1. **使用 SSH 密钥认证** (而不是密码)
   ```bash
   # 生成 SSH 密钥对
   ssh-keygen -t rsa -b 4096
   
   # 复制公钥到服务器
   ssh-copy-id user@server-ip
   ```

2. **限制数据库文件权限**
   ```bash
   chmod 600 /path/to/database.sqlite
   chown your-user:your-group /path/to/database.sqlite
   ```

3. **定期备份数据库**
   ```bash
   # 在服务器上设置定时备份
   0 3 * * * cd /path/to/damoxing/server && npm run db:backup
   ```

4. **不要在生产环境直接修改数据**
   - 在测试环境验证 SQL 语句
   - 修改前备份数据库
   - 使用事务确保数据一致性

## 数据库表结构

### 1. sys_menu (系统菜单表)

存储系统导航菜单数据。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY | 主键,自增 |
| `label` | TEXT | NOT NULL | 菜单名称 |
| `subtitle` | TEXT | | 菜单副标题 |
| `page_key` | TEXT | UNIQUE, NOT NULL | 页面标识,唯一 |
| `path` | TEXT | NOT NULL | 路由路径 |
| `icon` | TEXT | | 菜单图标 |

**索引**:
- `idx_menu_page_key` on `page_key`

**示例数据**:
```sql
id=1, label='贷款风险分析', subtitle='实时监控贷款风险指标', 
page_key='loan_risk', path='/dashboard/loan_risk', icon='fa fa-chart-line'
```

---

### 2. sys_page_template (页面模板表)

存储页面的 AMIS Schema 配置,支持版本管理。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY | 主键,自增 |
| `page_key` | TEXT | NOT NULL | 页面标识 |
| `title` | TEXT | NOT NULL | 页面标题 |
| `schema` | TEXT | NOT NULL | AMIS Schema (JSON 字符串) |
| `version` | INTEGER | DEFAULT 1 | 版本号 |
| `is_active` | INTEGER | DEFAULT 1 | 是否激活 (1=激活, 0=备份) |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**索引**:
- `idx_page_template_page_key` on `page_key`
- `idx_page_template_active` on `is_active`

**唯一约束**:
- `UNIQUE(page_key, version)` - 同一页面的版本号不能重复

**示例数据**:
```sql
id=1, page_key='loan_risk', title='贷款风险分析', 
schema='{"type":"page","title":"贷款风险分析","body":[...]}',
version=1, is_active=1
```

---

### 3. sys_dify_config (Dify AI 配置表)

存储每个页面的 Dify AI 工作流配置。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY | 主键,自增 |
| `page_key` | TEXT | UNIQUE, NOT NULL | 页面标识,唯一 |
| `workflow_name` | TEXT | NOT NULL | 工作流名称 |
| `api_url` | TEXT | NOT NULL | Dify API 地址 |
| `api_key` | TEXT | NOT NULL | Dify API 密钥 |
| `enabled` | INTEGER | DEFAULT 1 | 是否启用 (1=启用, 0=禁用) |
| `description` | TEXT | | 配置描述 |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**索引**:
- `idx_dify_page_key` on `page_key`
- `idx_dify_enabled` on `enabled`

**示例数据**:
```sql
id=1, page_key='loan_risk', workflow_name='贷款风险分析工作流',
api_url='https://api.dify.ai/v1', api_key='app-xxxxxxxx',
enabled=1, description='生产环境工作流'
```

---

### 4. sys_backend_config (后端配置表)

存储系统后端配置参数,如 API 限流设置。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY | 主键,自增 |
| `config_key` | TEXT | UNIQUE, NOT NULL | 配置键,唯一 |
| `config_value` | TEXT | NOT NULL | 配置值 (字符串) |
| `config_type` | TEXT | DEFAULT 'string' | 配置类型 (string/number/boolean/json) |
| `description` | TEXT | | 配置描述 |
| `updated_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**索引**:
- `idx_backend_config_key` on `config_key`

**默认配置**:
```sql
config_key='global_rate_limit_window', config_value='900000', config_type='number'
config_key='global_rate_limit_max', config_value='100', config_type='number'
config_key='ai_rate_limit_window', config_value='60000', config_type='number'
config_key='ai_rate_limit_max', config_value='10', config_type='number'
```

---

### 5. migrations (迁移记录表)

记录已执行的数据库迁移,由系统自动维护,**不要手动修改**。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY | 主键,自增 |
| `name` | TEXT | UNIQUE, NOT NULL | 迁移文件名 |
| `executed_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 执行时间 |

## 表关系说明

### 关系图

```
┌─────────────────┐
│   sys_menu      │
│  (系统菜单)      │
│                 │
│  - page_key ────┼──────┐
└─────────────────┘      │
                         │ (1:1)
                         │
                    ┌────▼──────────────────┐
                    │  sys_page_template    │
                    │   (页面模板)           │
                    │                       │
                    │  - page_key ──────────┼──────┐
                    └───────────────────────┘      │
                                                   │ (1:1)
                                                   │
                                              ┌────▼──────────────┐
                                              │ sys_dify_config   │
                                              │  (AI 工作流配置)   │
                                              │                   │
                                              │  - page_key       │
                                              └───────────────────┘
```

### 关联关系

1. **sys_menu ↔ sys_page_template** (1:1)
   - 通过 `page_key` 关联
   - 一个菜单对应一个激活的页面模板 (`is_active=1`)
   - 一个页面可以有多个版本,但只有一个激活版本

2. **sys_page_template ↔ sys_dify_config** (1:0..1)
   - 通过 `page_key` 关联
   - 一个页面模板可以有 0 或 1 个 Dify 配置
   - 不是所有页面都需要 AI 功能

3. **关联规则**:
   - `page_key` 是关联的核心字段,必须在三个表中保持一致
   - 创建菜单时会自动生成 `path = /dashboard/{page_key}`
   - 删除菜单不会自动删除关联的页面模板和 Dify 配置

## 常用 SQL 语句

### 查询操作

#### 1. 查看所有菜单

```sql
SELECT * FROM sys_menu ORDER BY id;
```

#### 2. 查看所有激活的页面模板

```sql
SELECT page_key, title, version, is_active 
FROM sys_page_template 
WHERE is_active = 1
ORDER BY page_key;
```

#### 3. 查看某个页面的所有版本

```sql
SELECT id, page_key, title, version, is_active, created_at
FROM sys_page_template
WHERE page_key = 'loan_risk'
ORDER BY version DESC;
```

#### 4. 查看启用的 Dify 配置

```sql
SELECT page_key, workflow_name, enabled 
FROM sys_dify_config 
WHERE enabled = 1;
```

#### 5. 查看完整的页面配置 (菜单 + 模板 + AI)

```sql
SELECT 
    m.label AS 菜单名称,
    m.page_key AS 页面标识,
    m.path AS 路由路径,
    pt.title AS 页面标题,
    pt.version AS 模板版本,
    d.workflow_name AS AI工作流,
    d.enabled AS AI启用状态
FROM sys_menu m
LEFT JOIN sys_page_template pt ON m.page_key = pt.page_key AND pt.is_active = 1
LEFT JOIN sys_dify_config d ON m.page_key = d.page_key
ORDER BY m.id;
```

#### 6. 查找没有页面模板的菜单

```sql
SELECT m.page_key, m.label
FROM sys_menu m
LEFT JOIN sys_page_template pt ON m.page_key = pt.page_key AND pt.is_active = 1
WHERE pt.id IS NULL;
```

#### 7. 查找没有 AI 配置的页面

```sql
SELECT m.page_key, m.label
FROM sys_menu m
LEFT JOIN sys_dify_config d ON m.page_key = d.page_key
WHERE d.id IS NULL;
```

### 更新操作

#### 1. 更新菜单信息

```sql
UPDATE sys_menu
SET 
    label = '新菜单名称',
    subtitle = '新副标题',
    icon = 'fa fa-new-icon'
WHERE page_key = 'customer_analysis';
```

#### 2. 更新页面模板 Schema

```sql
UPDATE sys_page_template
SET 
    schema = '{"type":"page","title":"更新后的页面","body":[]}',
    updated_at = CURRENT_TIMESTAMP
WHERE page_key = 'customer_analysis' AND is_active = 1;

UPDATE sys_page_template SET schema_json = readfile('dasd.json') WHERE page_key = 'eqweqw' and is_active=1;

```

#### 3. 激活某个版本的页面模板

```sql
-- 先将当前激活版本设为备份
UPDATE sys_page_template
SET is_active = 0
WHERE page_key = 'customer_analysis' AND is_active = 1;

-- 激活指定版本
UPDATE sys_page_template
SET is_active = 1
WHERE page_key = 'customer_analysis' AND version = 2;
```

#### 4. 启用/禁用 Dify 配置

```sql
-- 启用
UPDATE sys_dify_config
SET enabled = 1, updated_at = CURRENT_TIMESTAMP
WHERE page_key = 'customer_analysis';

-- 禁用
UPDATE sys_dify_config
SET enabled = 0, updated_at = CURRENT_TIMESTAMP
WHERE page_key = 'customer_analysis';
```

#### 5. 更新 Dify API 密钥

```sql
UPDATE sys_dify_config
SET 
    api_key = 'app-new-api-key',
    updated_at = CURRENT_TIMESTAMP
WHERE page_key = 'customer_analysis';
```

#### 6. 修改后端配置

```sql
-- 修改全局限流配置
UPDATE sys_backend_config
SET 
    config_value = '200',
    updated_at = CURRENT_TIMESTAMP
WHERE config_key = 'global_rate_limit_max';
```

### 删除操作

#### 1. 删除菜单

```sql
DELETE FROM sys_menu WHERE page_key = 'customer_analysis';
```

#### 2. 删除页面模板 (物理删除)

```sql
DELETE FROM sys_page_template WHERE page_key = 'customer_analysis';
```

#### 3. 删除页面模板 (软删除 - 推荐)

```sql
UPDATE sys_page_template
SET is_active = 0
WHERE page_key = 'customer_analysis';
```

#### 4. 删除特定版本的页面模板

```sql
DELETE FROM sys_page_template 
WHERE page_key = 'customer_analysis' AND version = 2;
```

#### 5. 删除 Dify 配置

```sql
DELETE FROM sys_dify_config WHERE page_key = 'customer_analysis';
```

#### 6. 删除整个页面 (菜单 + 模板 + AI 配置)

```sql
-- 按顺序删除,避免外键问题
DELETE FROM sys_dify_config WHERE page_key = 'customer_analysis';
DELETE FROM sys_page_template WHERE page_key = 'customer_analysis';
DELETE FROM sys_menu WHERE page_key = 'customer_analysis';
```

```sql
SELECT 
    page_key,
    title,
    schema,
    version + 1,  -- 版本号递增
    0             -- 设为备份状态
FROM sys_page_template
WHERE page_key = 'loan_risk' AND is_active = 1;

-- 3. 验证
SELECT version, is_active, created_at 
FROM sys_page_template 
WHERE page_key = 'loan_risk'
ORDER BY version DESC;
```

## 注意事项

### ⚠️ 重要提醒

1. **page_key 必须唯一**
   - `sys_menu.page_key` 必须唯一
   - `sys_dify_config.page_key` 必须唯一
   - `sys_page_template` 中 `(page_key, version)` 组合必须唯一

2. **page_key 格式要求**
   - 只能包含字母、数字、下划线和连字符
   - 推荐使用小写字母和下划线,例如: `loan_risk`, `customer_analysis`

3. **Schema 必须是有效的 JSON**
   - 插入前验证 JSON 格式
   - 使用 JSON 验证工具: https://jsonlint.com

4. **版本管理**
   - 每个 `page_key` 只能有一个 `is_active=1` 的版本
   - 创建新版本时,版本号必须递增
   - 不要删除激活版本,先激活其他版本再删除

5. **修改数据后需要清除缓存**
   - 菜单数据有缓存,修改后需要重启后端服务
   - 或者等待缓存自动过期 (默认 5 分钟)

6. **不要手动修改 migrations 表**
   - 该表由迁移系统自动维护
   - 手动修改可能导致迁移系统异常

7. **备份重要数据**
   - 修改前备份数据库: `cp database.sqlite database-backup.sqlite`
   - 或使用: `npm run db:backup`

## 数据库备份与恢复

### 备份数据库

```bash
cd server

# 方法 1: 手动复制
cp database.sqlite database-backup-$(date +%Y%m%d-%H%M%S).sqlite

# 方法 2: 使用内置脚本
npm run db:backup

# 方法 3: 导出为 SQL
sqlite3 database.sqlite .dump > database-backup.sql
```

### 恢复数据库

```bash
cd server

# 方法 1: 手动复制
cp database-backup-20251216.sqlite database.sqlite

# 方法 2: 使用内置脚本
npm run db:restore

# 方法 3: 从 SQL 导入
sqlite3 database.sqlite < database-backup.sql
```

### 重置数据库

```bash
cd server

# 删除数据库
rm database.sqlite

# 重新运行迁移
npm run db:migrate
```
