# 业务标准升级更新说明

本文档用于对应 `docs/业务标准升级方案.md` 中的 12 个改造点，整理各数据库需要执行的升级脚本、初始化脚本，以及每个改造点的简要更新内容，便于现场实施和投产核对。

## 1. 执行原则

### 1.1 已上线旧库

已存在业务标准相关基础表的环境，优先执行各数据库对应的升级脚本：

- Oracle：`server/data/upgrade_business_standards_online_oracle.sql`
- 达梦：`server/data/upgrade_business_standards_online_dm.sql`
- PostgreSQL：`server/data/upgrade_business_standards_online_pg.sql`
- GaussDB：`server/data/upgrade_business_standards_online_gauss.sql`
- 人大金仓：`server/data/upgrade_business_standards_online_kingbase.sql`

上述脚本当前主要覆盖改造点 `2、3、4、5、8、9、10` 的数据库结构变更，脚本均按“对象不存在才创建、字段不存在才新增”思路整理，可用于已上线库增量升级。

### 1.2 新建环境

如果是新建库或初始化部署，可直接执行各数据库对应的初始化脚本：

- Oracle：`server/data/init_business_standards_oracle.sql`
- 达梦：`server/data/init_business_standards_dm.sql`
- PostgreSQL：`server/data/init_business_standards_pg.sql`
- GaussDB：`server/data/init_business_standards_gauss.sql`
- 人大金仓：`server/data/init_business_standards_kingbase.sql`
- 本地默认脚本：`server/data/init_business_standards.sql`

初始化脚本包含当前业务标准主流程所需核心表结构，适用于全新环境一次性建表。

### 1.3 存储过程改造单独执行

改造点 `6` 属于存储过程/函数层升级，不在上述“业务标准升级脚本”主表结构范围内，需按数据库类型额外执行过程脚本。

### 1.4 基础数据初始化

改造点 `2` 的业务内容分类表 `gjj_ywnrfl` 建表后，还需要补齐基础数据。现场只需执行 `gjj_ywnrfl` 表的插入语句脚本：

- `server/data/GJJ_YWNRFL_202604131804.sql`

## 3. 12个改造点对应说明

| 改造点 | 是否涉及数据库脚本 | 已上线库执行脚本 | 新建库初始化脚本 | 更新内容简单说明 |
| --- | --- | --- | --- | --- |
| 1. 关键数据算法下拉改为本地 JSON 配置 | 否 | 无 | 无 | 算法下拉改为读取 `server/config/business-algorithms.json`，数据库表结构不变，现有算法编码继续沿用。 |
| 2. 业务内容分类改为自有维护并通过自有接口取值 | 是 | 对应数据库的 `upgrade_business_standards_online_*.sql` | 对应数据库的 `init_business_standards_*.sql` | 新增 `gjj_ywnrfl` 表，用于按关键算法维护业务内容分类；上线后还需初始化基础分类数据。 |
| 3. 标准库新增自定义编码字段 | 是 | 对应数据库的 `upgrade_business_standards_online_*.sql` | 对应数据库的 `init_business_standards_*.sql` | 在 `gjj_ywbzk` 增加 `zdybm` 字段，并补充唯一索引，供后续按稳定编码识别业务标准。 |
| 4. 标准库新增业务办理分类字段并优化新增、修改页面展示 | 是 | 对应数据库的 `upgrade_business_standards_online_*.sql` | 对应数据库的 `init_business_standards_*.sql` | 在 `gjj_ywbzk` 增加 `ywblfl` 字段，区分“标准/条件”模板，并给历史数据补默认值 `1`。 |
| 5. 业务办理标准支持配置互斥关系 | 是 | 对应数据库的 `upgrade_business_standards_online_*.sql` | 对应数据库的 `init_business_standards_*.sql` | 新增 `gjj_ywbzkhc` 互斥关系表，用于限制同一分类下冲突标准不能同时勾选。 |
| 6. 关键数据算法按不同子存储过程执行 | 是，属于过程脚本 | Oracle 执行 `server/data/oracle-存储-260414.sql`，达梦执行 `update_calc_objects_dm.sql`；PG-family 按各自过程脚本执行 | Oracle/达梦初始化后继续执行过程脚本；PG-family 需补数据库识别函数和公共过程脚本 | 保留统一入口，按算法分发到不同子过程；Oracle 如需兼容 JSON 方言 SQL，需补执行 `server/data/update_sql_dialect_resolver_oracle.sql`。 |
| 7. 第三方程序对接范围补齐 | 否 | 无 | 无 | 主要是外围系统调用范围补齐和统一接入方式调整，不新增业务标准专用表结构。 |
| 8. 业务办理标准值在清册选择列表中按 X 占位反显 | 是 | 对应数据库的 `upgrade_business_standards_online_*.sql` | 对应数据库的 `init_business_standards_*.sql` | 仓库现有脚本中补充了 `gjj_ywbz.ywbzz` 字段，用于承接业务标准值；页面展示层按 `X` 占位替换最终文案。 |
| 9. 调试功能支持业务参数自动生成及成功案例保存反显 | 是 | 对应数据库的 `upgrade_business_standards_online_*.sql` | 对应数据库的 `init_business_standards_*.sql` | 新增 `gjj_ywbz_debug_case` 表，用于保存调试成功案例、请求 JSON 和结果摘要。 |
| 10. 标准库新增提示语属性名称和提示语属性单位 | 是 | 对应数据库的 `upgrade_business_standards_online_*.sql` | 对应数据库的 `init_business_standards_*.sql` | 在 `gjj_ywbzk` 增加 `tsysxmc`、`tsysxdw` 两个提示语字段，允许为空。 |
| 11. 标准库属性组支持自定义属性录入 | 否 | 无 | 无 | 继续复用 `gjj_ywbzksx` 现有字段含义，通过 `ywblbzdx` 是否为空区分对象属性和自定义属性，不新增表字段。 |
| 12. 业务规则页面新增 AI 政策分析辅助清册勾选 | 否 | 无 | 无 | 复用现有业务规则表和 `sys_dify_config` 工作流配置表，新增的是接口、页面交互和 AI 配置，不新增业务标准专用 DDL。 |

## 4. 分数据库执行建议

### 4.1 Oracle

建议执行顺序：

1. 已上线库先执行 `server/data/upgrade_business_standards_online_oracle.sql`
2. 如涉及改造点 6，再执行 `server/data/oracle-存储-260414.sql`
3. 如需补 SQL 方言解析函数，再执行 `server/data/update_sql_dialect_resolver_oracle.sql`
4. 如涉及改造点 2 的分类基础数据，再补执行 `server/data/seed_ywnrfl_gjsjsf_1_oracle.sql`

### 4.2 达梦

建议执行顺序：

1. 已上线库先执行 `server/data/upgrade_business_standards_online_dm.sql`
2. 如涉及改造点 6，再执行 `server/data/update_calc_objects_dm.sql`
3. 如只补 SQL 方言解析函数，可单独执行 `server/data/update_sql_dialect_resolver_dm.sql`
4. 如果现场历史表主键仍存在 `IDENTITY` 兼容问题，可视情况执行 `server/data/migrate_dm_identity_to_auto_increment.sql`

### 4.3 PostgreSQL

建议执行顺序：

1. 已上线库先执行 `server/data/upgrade_business_standards_online_pg.sql`
2. 新环境如仅建业务标准表，执行 `server/data/init_business_standards_pg.sql`
3. 如涉及改造点 6 的过程执行链路，再补执行 `server/data/init_pg_family_db_format_pg.sql`
4. 再执行 `server/data/init_pg_family_calc_objects_common.sql`
5. 如只补 SQL 方言解析函数，可参考 `server/data/update_sql_dialect_resolver_pg_family.sql`

### 4.4 GaussDB

建议执行顺序：

1. 已上线库先执行 `server/data/upgrade_business_standards_online_gauss.sql`
2. 新环境如仅建业务标准表，执行 `server/data/init_business_standards_gauss.sql`
3. 如涉及改造点 6，再执行 `server/data/init_pg_family_db_format_gauss.sql`
4. 再执行 `server/data/init_pg_family_calc_objects_common.sql`
5. 最后执行 `server/data/init_pg_family_calc_objects_gauss_compat.sql`

### 4.5 人大金仓

建议执行顺序：

1. 已上线库先执行 `server/data/upgrade_business_standards_online_kingbase.sql`
2. 新环境如仅建业务标准表，执行 `server/data/init_business_standards_kingbase.sql`
3. 如涉及改造点 6，再执行 `server/data/init_pg_family_db_format_kingbase.sql`
4. 再执行 `server/data/init_pg_family_calc_objects_common.sql`

## 5. 重点注意事项

- 改造点 `3` 的 `zdybm` 唯一索引创建前，需先检查历史数据是否有重复非空编码，否则升级脚本可能执行失败。
- 改造点 `4` 的 `ywblfl` 默认值建议统一为 `1`，升级后需确认历史空值是否已补齐。
- 改造点 `2` 虽然建表脚本已包含 `gjj_ywnrfl`，但业务可用还依赖分类基础数据初始化。
- 改造点 `6` 属于存储过程层改造，不能只执行表结构脚本，需要配套执行过程/函数脚本。
- 改造点 `8` 按仓库当前 SQL 实现，已在升级脚本中补充 `gjj_ywbz.ywbzz` 字段，现场应以实际脚本为准。
- 改造点 `12` 不新增业务标准专用表，但依赖现有 AI 工作流配置能力，需提前确认 `sys_dify_config` 及页面级配置链路可用。

## 6. 推荐实施口径

建议现场统一按以下口径执行：

1. 先判断是“已上线旧库升级”还是“新环境初始化”。
2. 先执行业务标准主表脚本，再执行改造点 `6` 的过程脚本。
3. 再补基础数据初始化和页面级配置。
4. 最后按 12 个改造点逐项验证页面展示、接口保存、规则勾选、调试案例和 AI 分析能力。
