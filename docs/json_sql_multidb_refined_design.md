# 标准库 SQL 多数据库展示与 default 回退方案

## 1. 方案目标

本方案用于统一标准库 SQL 的多数据库维护与执行规则。

当前需要解决的问题是：

- 前端要支持为同一条标准结果 SQL、属性来源 SQL 维护多份数据库版本
- 配置时要有一个 `default` 版本
- 执行时遵循“当前数据库专属 SQL 优先，未配置时回退到 `default`”的规则
- 后端仍然按字符串方式落库
- 真正存在数据库差异的重点是标准库 SQL 与存储过程/函数执行链路

## 2. 方案结论

采用“前端维护多数据库 SQL，运行时按当前数据库优先、default 回退，后端继续字符串落库”的方案。

核心原则如下：

1. 不改表结构
2. 不新增表
3. 后端仍按字符串写入 `gjj_ywbzk.ywbzjg`、`gjj_ywbzksx.ywblbzyg`
4. 前端继续支持多数据库 SQL 维护，但增加 `default` 维度
5. 运行时统一采用“当前数据库方言优先，缺失时回退到 `default`”
6. 旧版纯 SQL 文本继续兼容，等价视为“只有 default”
7. 普通列表、详情、增删改查链路不做过度扩展，仍按当前数据库通用 SQL 运行

## 3. 方案边界

本方案不做以下事情：

1. 不重做整套后端多数据源路由架构
2. 不把普通 CRUD SQL 全量改造成多方言规则系统
3. 不新增标准库 SQL 变体表
4. 不把规则执行逻辑拆成全新的应用层执行引擎
5. 不要求所有数据库都必须先各配一份专属 SQL 才能上线

本方案只处理以下对象：

1. `gjj_ywbzk.ywbzjg`
2. `gjj_ywbzksx.ywblbzyg`
3. 前端标准库维护页面对上述两类字段的展示与编辑
4. 存储过程/函数对上述两类字段的解析与回退

## 4. 存储格式方案

### 4.1 继续使用字符串落库

保持以下字段不变：

- `gjj_ywbzk.ywbzjg`
- `gjj_ywbzksx.ywblbzyg`

后端继续直接保存字符串，不新增列，不拆表。

### 4.2 JSON 数组文本

字段内容统一采用 JSON 数组文本表达多数据库 SQL 配置。

推荐格式：

```json
[
  {
    "dialect": "default",
    "sql": "select ... from ..."
  },
  {
    "dialect": "oracle",
    "sql": "select ... from dual"
  },
  {
    "dialect": "dm",
    "sql": "select ..."
  }
]
```

### 4.3 default 的含义

`default` 是一个保底 SQL，不代表某个具体数据库类型。

适用场景：

- 当前数据库没有专属 SQL
- 该 SQL 本身是通用 SQL
- 新接入数据库先复用默认版本，后续再补专属版本

### 4.4 旧数据兼容

旧版纯 SQL 字符串继续支持。

兼容规则：

1. 空值：按空 SQL 处理
2. 非 JSON 文本：视为旧版单 SQL，等价于“隐式 default”
3. JSON 数组：按 `dialect` 规则解析

也就是说，旧数据无需立即迁移。

## 5. 方言与优先级规则

### 5.1 dialect 取值

- `default`
- `oracle`
- `dm`
- `pg`
- `db2`
- `gauss`
- `kingbase`
- `oceanbase_oracle`
- `oceanbase_pg`

### 5.2 运行时优先级

统一规则如下：

1. 先取当前数据库类型完全匹配的 SQL
2. 如果没有，则取 `default`
3. 如果字段本身是旧版纯 SQL，则直接使用原文本
4. 如果是 JSON 但既没有当前数据库 SQL，也没有 `default`，则视为缺失配置并报错

### 5.3 为什么需要 default

`default` 的作用是：

- 让通用 SQL 可以先落地
- 让新接入数据库在缺少专属 SQL 时仍有回退路径
- 让只有少数方言差异的规则不用重复配置所有数据库版本

## 6. 前端方案

### 6.1 页面目标

前端不是要变成复杂的 SQL 管理平台，而是提供一个清晰、低成本的维护入口。

建议页面采用：

- 一个 `Default` 页签
- 若干数据库专属页签

例如：

- `Default`
- `Oracle`
- `DM`
- `PG`
- `DB2`
- `Gauss`
- `Kingbase`
- `OB Oracle`
- `OB PG`

### 6.2 页面保存规则

保存时：

1. 优先读取各页签内容
2. 将非空页签组装为 JSON 数组文本
3. 原样提交给后端

页面不需要关心数据库执行逻辑，只负责把配置整理成字符串。

### 6.3 页面读取规则

读取时：

1. 若是旧版纯 SQL，则回显到 `Default` 页签
2. 若是 JSON，则按 `dialect` 拆分到对应页签
3. 不存在的页签保持为空

### 6.4 一键转换规则

一键转换的目标为：

- 旧版纯 SQL -> `default`

这样处理的原因是：

- 旧版单 SQL 的真实语义更接近“通用 SQL”
- 直接转成 `default` 更符合回退逻辑
- 可减少后续维护重复内容

## 7. 后端方案

### 7.1 后端职责

后端在本方案中的职责只有三类：

1. 校验 SQL 配置字符串是否合法
2. 原样保存 / 原样返回
3. 在需要执行 SQL 的地方，按“当前库优先 + default 回退”解析出最终 SQL

### 7.2 保持字符串落库

`ywbzk.js`、`ywbz.js` 继续保持以下模式：

- 接收字符串
- 校验字符串
- 保存字符串

不把 JSON 拆到关系表中。

### 7.3 解析工具调整

解析工具需要补齐以下能力：

1. 支持 `default`
2. SQL 解析增加回退逻辑
3. 旧版 SQL 转 JSON 时默认生成 `default`
4. 摘要、审计等接口把 `default` 视为合法配置项

### 7.4 普通 CRUD 处理原则

标准库、规则库的列表、详情、保存、删除等接口仍沿用现有数据库通用 SQL。

理由：

- 这些 SQL 主要是基础表操作
- 当前数据库之间兼容性较高
- 真正有数据库差异的部分在规则执行 SQL，不是这些接口本身

## 8. 存储过程与函数方案

### 8.1 存储过程必须调整

本轮真正必须改的数据库对象，不是普通表操作，而是：

- 主过程
- 取 SQL 的函数
- 与 `ywbzjg / ywblbzyg` 直接执行有关的辅助对象

### 8.2 调整重点

调整点不在重写整个业务过程，而在执行前取哪段 SQL。

过程内统一改成：

1. 读取字段原始字符串
2. 判断是不是 JSON
3. 先取当前数据库类型 SQL
4. 没有则取 `default`
5. 得到最终 SQL 后，再执行原有变量替换和动态执行

### 8.3 过程层建议

为了少动主过程本体，建议采用“主过程 + 辅助函数”的方式：

- 新增或改造一个“从 SQL 配置字符串中选出最终 SQL”的函数
- 主过程只调用该函数

这样能把改动集中到一个点，便于 Oracle、达梦、PG-family 分别维护。

## 9. 开发实施顺序

### 第一阶段：解析与回退规则

1. 解析工具增加 `default`
2. 解析优先级改为“当前库 -> default -> 旧版文本”
3. 旧版 SQL 转 JSON 的结果默认生成 `default`

### 第二阶段：页面补充 default

1. 标准结果 SQL 增加 `Default` 页签
2. 属性来源 SQL 增加 `Default` 页签
3. 页面回显时旧版单 SQL 自动落到 `Default`
4. 页面保存时优先拼装 `default + 各数据库专属`

### 第三阶段：后端接口细化

1. 保存接口允许 `default`
2. 摘要接口展示 `default`
3. 审计接口识别“无专属 SQL 但有 default”的合法状态

### 第四阶段：存储过程/函数改造

1. Oracle
2. 达梦
3. PG-family

统一按“专属优先，default 回退”取 SQL。

### 第五阶段：回归验证

1. 旧版单 SQL 数据可正常展示、保存、执行
2. 仅配 `default` 的 JSON 数据可正常执行
3. 同时配置 `default + oracle` 时，Oracle 优先取 `oracle`
4. 同时配置 `default + pg` 时，PG-family 优先取 `pg`
5. 缺少专属且缺少 `default` 时，能够给出明确错误

## 10. 验证范围

本方案需要验证，但验证范围应收敛，不应扩散为“全系统所有功能重测”。

建议只覆盖以下链路：

1. 标准库页面新增、编辑、查看
2. 标准库导入、导出
3. 规则同步到业务规则
4. 调试执行接口
5. 存储过程实际取 SQL 并执行
6. 旧数据兼容

## 11. 一句话结论

前端负责维护 `default + 各数据库专属 SQL`，后端继续按字符串落库，执行链路统一按“当前数据库优先、default 回退、旧版单 SQL 兼容”的规则取出最终 SQL，存储过程只在取 SQL 这一步做最小兼容改造。
